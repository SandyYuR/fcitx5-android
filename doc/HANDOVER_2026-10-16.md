## 已完成的工作

### 1. 直连引擎实现（`DirectRimeEngine.kt`，432 行）

实现了 `FcitxAPI` 接口，不经过 fcitx5，Kotlin 直接调 JNI → `libdirect_rime.so` → librime：

- **生命周期**：`start()` 先调 `DataManager.sync()` 同步 assets 到磁盘，再用 `RimeThreadOwner` 单线程派发到 librime
- **按键**：四个 `sendKey` 重载收敛到 `dispatchKey(keyCode, metaState, unicodeChar, up)`，native 侧做 KeyEvent → keysym/mask 映射与部署期门控
- **事件回流**：`publish(snapshot)` 把 native 返回的 `RimeSnapshot` 翻译成 `CommitStringEvent` / `InputPanelEvent` / `PagedCandidateEvent`，UI 层零改动
- **代次门控**：`generation.bind { … }.let { generation.consume(it) }`，焦点切换后过期结果被丢弃（防 A 输入框候选落在 B 上）
- **线程 owner**：所有 librime 调用经 `RimeThreadOwner("rime-main")` 单线程，非线程安全约束
- **部署门控**：`DeployKeyGate` 与 native 的 `deploy` 通知联动，部署期按键被吞且不落回编辑器
- **数据目录**：`shared = <dataDir>/usr/share/rime-data`、`user = <dataDir>/rime`，与 `fcitx5-rime/rimeengine.cpp:337/447/457-459` 对齐

### 2. 接口抽象（`InputEngineBackend.kt`，20 行）

```kotlin
interface InputEngineBackend : FcitxAPI, FcitxLifecycleOwner {
    fun start()
    fun stop()
}
```

`Fcitx`（走 fcitx5）与 `DirectRimeEngine`（直连 librime）都实现它，`FcitxDaemon` 只依赖接口。

### 3. 接线（`FcitxDaemon.kt`）

private val backend: InputEngineBackend by lazy {
