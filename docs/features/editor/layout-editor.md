# 键盘布局编辑器

本版提供完整的 **应用内键盘布局编辑器**，配合底层的 JSON 配置文件 (`config/TextKeyboardLayout.json`)，允许你：

- 不写代码、所见即所得地改键盘
- 同时拥有 JSON 可手改、可版本管理、可分享的能力

::: tip 编辑器预览与真机同源
编辑器预览与真机键盘**共用同一套按键解析与渲染逻辑**——有助于在编辑时发现问题；真实显示仍受屏幕尺寸、形态、当前方案和主题影响。若"编辑器里对、真机不对"，优先检查是否编辑对了目标布局（看子模式下拉框与工具栏副标题）。主题页与分体校准页的预览同样按当前启用布局的默认排列绘制，逐键颜色与真实键盘一致。
:::

## 核心能力

| 能力 | 说明 |
|------|------|
| 多布局文件 | 支持多个 TextKeyboardLayout profile，方便不同场景切换 |
| 子模式布局 (submode) | 按 Rime 方案分别定制键位布局 |
| 子模式「默认」项 | 下拉框第一项固定是「默认」——编辑所有无专用布局方案共用的那份（本版） |
| 分体布局按子布局配置 | 为默认布局或某个方案单独配一套分体排列（本版） |
| 合成中预览 | 模拟当前排列已配置的合成态按键，支持与分体预览同时使用 |
| 分体单行连贯 | 在分体排列的行设置中关闭该行分体 |
| 层切换 (layer) | 通过 MacroKey `to/osl` action 在布局层间跳转 |
| 行高百分比 | 按行配置相对高度；同行取最大值，所有行再归一化 |
| 按键宽度权重 | weight 字段：省略走类型默认，`0` 参与分配剩余宽度，正数按整行比例占宽 |
| 空白占位键 | 不可交互的重量占位，用于调位置与分体推挤（本版） |
| 空格键划动动作 | 为空格配置划动动作与标签（与光标移动开关互斥，本版） |
| 空格键标签 | 给空格键填固定键面文字；留空按方案名显示（本版） |
| 主题色 token | 按键颜色可引用主题色 token，跟随主题切换 |
| 全量校验 | 编辑过程中进行完整数据校验，避免崩溃 |
| 退出确认 | 未保存变更时弹出确认对话框 |

## 入口

- **应用主页 → 键盘 → 键盘布局自定义 → 修改键盘定义**
- 同页还有：**键盘布局管理**（完整的布局文件列表，页头切换图标用于切换当前启用布局）、**数字键盘布局**、**弹出字符设定**、**在线编辑器**；新建／重命名／删除布局文件在编辑器右上角菜单中
- 也可以在电脑浏览器中使用 [在线编辑器](https://sandyyur.github.io/f5a-see-me/){target="_blank" rel="noopener"} 修改布局，再通过二维码导入到手机端

## 布局 Profile 与切换

进入“键盘布局管理”时默认只展开当前启用的布局，其余配置收起；可以逐项展开查看。当前页面内手动展开／收起和屏幕旋转会保留状态，重新进入页面重新以当前启用项为默认。收起选中配置时，高亮覆盖整个标题卡片，不留下异色底边。页头的切换图标打开布局选择菜单；切换只改变当前启用的 Profile，不改变列表里已有的展开／收起状态。

TextKeyboard 布局支持多个 **Profile**。每个 Profile 对应一份完整的文本键盘布局 JSON 文件，适合保存不同用途的键盘配置（日常输入、单手布局、符号增强、实验布局等）。

文件命名规则：

| Profile | 文件 |
|---------|------|
| `default` | `config/TextKeyboardLayout.json` |
| 其他名称 | `config/TextKeyboardLayout.<profile>.json` |

在应用内可以：

- 在键盘布局编辑器中创建、复制、重命名、删除不同 Profile
- 在 **键盘布局管理** 页头点击切换图标，选择当前启用的 Profile
- 将 **TextKeyboard 布局文件选择** 动作放到 Kawaii Bar，输入时快速切换 Profile

Profile 切换的是整份布局文件；它不同于布局 JSON 内部的 `layer` 切换，也不同于 `LayoutSwitchKey` 在当前布局内跳到某个布局目标。

已解锁时，应用会自动把当前选中的布局同步为设备保护存储快照，重启后首次解锁前也可用于文字密码键盘。没有可用快照、密码布局解析失败或没有按键时，最终回退内置 26 键；数字密码使用数字盘。锁屏输入不依赖中文方案，首次解锁后恢复正常 Profile，不把回退布局保存成日常选择。详见[首次解锁前启动](/troubleshooting/oem-startup#重启后首次解锁前无法输入)。

## 子模式下拉框与「默认」项

选中 `rime` 这类带方案的布局后，编辑器顶部出现**子模式下拉框**，**第一项固定是「默认」**，其后是各方案名：

- **选「默认」**：编辑布局文件里 `"rime": { "default": [...] }` 那份——它同时是**所有没有专用布局的方案实际使用的布局**；
- **选某个方案**：编辑该方案专用布局；没有专用布局时提示"正在编辑…的默认布局"，下拉框下方出现「**为当前方案创建专用布局**」按钮（也在「新增布局…」菜单中），确认后新建；
- 工具栏副标题始终显示当前**实际**编辑的位置，格式为「布局文件 › 布局 › 默认／方案 › 普通排列／分体排列」（如 `默认 › rime › 默认 › 普通排列` 就是默认布局），不会出现"以为在改 A、其实改了 B"；
- 打开编辑器时若当前方案没有专用布局，下拉框自动停在「默认」项。

### 方案名称与当前编辑位置

已有方案 ID 键时，编辑器选择实际的 ID 子布局，不再重复列同一方案的显示名称；仅有旧名称键的配置仍按原键编辑，不会自动改名。没有专用布局时仍回退“默认”。
在键盘结构页面通过行标题栏新增或移动行，首末行只显示合法方向；行拖动卡片采用不透明底色，避免叠在其他行上时文字穿透。
从子编辑页返回时只合并已确认的结果。未保存更改先确认保存或放弃；页面重建可恢复主体草稿，不等于任何时点强杀都能保留尚未确认的弹窗内容。
宏动作以对话框叠加在当前按键表单上；确认后回到原表单，布局文件仍以最终保存为准。
动作选择“输入文本”后，点击文本框可调用当前系统输入法，支持正常组合输入与退格；从其他动作类型切到“输入文本”，以及新增步骤后，也保留这一能力。工具栏自定义按钮的宏编辑共用同一表单，确认只回填动作草稿。

## 层子布局与数字键盘

数字、符号等独立层也可在子布局列表中预览和编辑，显示为「层：数字」，文件中仍保留 `__layer__:数字` 这样的存储键。它们用于切层，不会被当成 Rime 输入方案。每个层子布局都可以拥有自己的普通排列、分体排列、高度和辅助栏；同一子布局的普通与分体排列共用竖／横屏高度及辅助栏。

数字输入框按以下顺序选用键盘：可解析的「数字键盘布局」偏好 → 当前布局自带的数字层 → 内置数字键盘。自动匹配接受「数字」「数字键盘」「123」「?123」「numpad」等常见名称，也支持文件中的独立数字布局条目；显式偏好失效后重新自动发现，不会继续引用已删除的层。选择「内置数字键盘」则固定使用内置数字盘。

网页端可在「新建」中选择「层子布局」，填写层名并选择复制来源；操作说明与当前发布状态见[在线编辑器](/features/online-editor)。

## 分体键盘布局（按子布局配置）

方案下拉框正下方同一行有 **「合成中」** 和 **「分体排列」** 两个勾选项。“合成中”位于左侧，只模拟预览的合成态覆盖，不保存到 JSON，也不改变手机当前输入状态；可以和分体预览一起使用。`text_editor` 使用专用面板预览，不显示合成中选项。

“分体排列”控制编辑哪份排列：

- 勾选后进入**当前选中的那个子布局**（默认布局或某方案）的分体布局编辑；
- 该子布局还没有分体布局时，会先询问"要从它当前的排列复制一份开始编辑吗"，**不静默新建**；
- 勾选框右侧实时显示状态（已有独立分体布局 / 未单独设置沿用普通布局）；长按勾选框有完整说明；
- 勾选状态下右上角菜单「**删除当前排列…**」删除的是这一份分体布局，普通排列保留；「新增布局…」菜单中的「**复制为分体排列**」在已有分体布局时置灰；
- 预览会**按分体渲染**你正在编辑的那份，即使预览框宽度不触发分体；
- 磁盘上写在子布局对象内部的 `__variant__:split` 键（与 `default` 平级）——这是机器内部键名，请勿当成方案名使用。

分体的断点、中缝对齐与占位键用法见 [分体键盘](/features/keyboard/split-keyboard)。

在分体排列的“键盘结构”中打开行设置，勾选“本行保持连在一起”后，该行按整行显示，其他行照常分体。该行不应用分体断点或自动中间键复制。保存后标记写在行首按键的 `splitRowDisabled` 字段；编辑、删除或移动按键时，编辑器保持行设置归属，不把它误带到另一行。

## 按键类型下拉框

- 每个按键类型都带**本地化中文说明**（本版新增），选型时直接看到用途；
- 本版新增 **空白占位键** 类型：只占位、完全不接收触摸（不震动、无高亮、不吃滚动），键列表中显示为 `·` 记号；
- [StickyModifierKey 粘滞修饰键](/features/keys/sticky-modifier-key) 可选择 Ctrl / Shift / Alt；切换时同步空标签或默认标签，保留自定义标签。`text_editor` 不提供此类型；旧布局或恢复草稿中的已有值保留为禁用选项，保存该按键前必须明确改为受支持的类型；
- AlphabetKey / MacroKey 的**显示文本优先**规则在编辑器预览与保存中一致生效（见 [AlphabetKey](/features/keys/alphabet-key) / [MacroKey](/features/keys/macro-key)）。

## 内置布局

首次启动时应用会自动安装一批**社区贡献的布局**（大同-9+18+26keys、九键布局、行之-26键、行之-万象九键v2、QM-朝花、Sandy-数字行26+万象九键，以及成套主题配套的水彩、普蓝），首次铺设时把第一份设为当前布局（已选择其他布局或已有自己的 `TextKeyboardLayout.json` 时不改）：

- 内置布局是普通文件：编辑、重命名照常工作；**删除内置布局文件后，下次启动会按原名重新补装**，不想看到可改用其他布局文件；
- 版本更新会更新内置布局内容，但**只替换从未被用户修改过的文件**——你保存过的文件始终保留；
- 26 键字母层宏键的冗余显示文本已清理；部分布局的 `⌨` 键长按已接 Rime 方案选单宏。

## 健壮性（本版持续加固）

- 布局加载 / 解析 / 序列化 / 写入**全部移出主线程**，预览走独立布局通道，不再清空全局缓存；
- 布局保存**原子化**，草稿改存私有文件（修复编辑大布局时 `TransactionTooLargeException` 崩溃），快照名经白名单与 canonical path 校验阻断路径穿越；
- 带注释的布局 JSON 解析不再静默回退；拖拽松手归位、旋屏状态保存、拖拽排除添加键等问题已修复。
