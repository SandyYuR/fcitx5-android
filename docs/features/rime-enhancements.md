# 中州韵引擎设置

中州鹅直接调用 librime，保留完整 Android 键盘和设置。
原生 Fcitx Core、fcitx5-rime 及 AndroidFrontend 已移除；默认内置 Rime 无需另装 APK，可选的引擎提供 APK 见[中州韵引擎变体](./rime-engine-variants)。
APK 不预装中文方案、完整词典或万象模型，见[快速上手](/guide/quick-start)。

设置首页的「中州韵引擎」分栏位于「日常调整」之前，包含本页、[中州韵引擎变体](./rime-engine-variants)和[中州韵方案更新](./rime-scheme-updates)三个入口。引擎设置页依次提供启用的输入方案、编辑器内预编辑、用户数据目录、数据目录管理、导入 Rime 方案 ZIP、重新部署、同步用户词典，以及页尾的密码框开关。

## 目录、导入与部署

「设置首页 → 中州韵引擎 → 中州韵引擎设置」提供方案、预编辑、数据目录、导入、部署与同步。
导入完整方案依赖，或将文件放到当前目录并在 `default.custom.yaml` 配置 `schema_list`。
显式重新部署会重建 Rime 环境，重读 Lua、方案列表与开关；以实际候选和开关变化判断结果。
部署期间不接收输入，模型二进制和用户词库不因重部署清空。

### 部分部署失败时的降级

使用 librime-evo 引擎和部分方案时，部署日志可能仍显示 failure，例如缺少只被间接引用的包装词典；只要 `<user>/build/default.yaml` 是普通文件、引擎能列出方案、当前方案的 `build/<schema>.schema.yaml` 非空，且当前方案主词典的 `build/<dict>.table.bin` 与主 prism 的 `build/<prism>.prism.bin` 都存在且非空，应用会保留失败记录但允许继续输入。任一条件不满足时仍失败关闭。

当前方案优先取活动会话；没有会话时，`switcher/fix_schema_list_order: true` 使用方案列表首项，否则读取 `<user>/user.yaml` 的 `previously_selected_schema`，仅当它仍在方案列表中才使用。词典名来自当前方案的 `translator/dictionary`；主 prism 优先取 `translator/prism`，或从 `translator/prisms` 的 `input_types` 引用／列表中按当前输入类型取 `name`；未声明时使用 `build/dictionaries/<dict>/algebra` 的首个分组。显式名称优先限定为 `<dict>.<prism>`。旧引擎缺少相应查询 API 时退回 YAML 与文件检查。

降级不表示方案完整、所有词典已编译或模型能力已验证；日志、失败通知和缺失文件保持原样，应用不会自动补文件。主词典或棱镜缺失、Lua 或模型不兼容仍可能导致没有候选，必须实际输入验证。

用户词典同步会等待实际完成；启动成功不等于同步成功，失败会明确返回错误。同步及备份保存的维护阶段会暂停引擎输入。

状态栏同步入口会显示失败原因，失败不应使输入法进程崩溃。`.temp.userdb` 是引擎恢复流程的临时库；修复后的引擎会在整批同步前回收旧临时库，并在枚举时精确跳过这一保留名称，不把它当作普通用户词典，也不通过递归删除陌生文件来绕过错误。此行为需要包含该修复的引擎 SDK，应用侧异常处理与引擎修复分别验证，见[设备问题复核](/maintainer/changes/2026-11-06-device-fixes)。

这个临时库通常由用户词典同步中的快照合并、词库恢复或旧格式升级创建。同步会读取同步目录中已有的 `*.userdb.txt`，也可能包括本机先前生成的快照，因此并非只有多设备同步才会创建临时库。恢复在打开临时库前先清除旧数据库，并在打开、合并及退出路径上执行清理；若临时库仍被占用或删除失败，本次同步会失败并保留现场，而不会复用旧内容。它的存在不等于方案损坏，也不能仅凭同步失败日志判断最初是哪次操作留下的。

## 引擎变体

「设置首页 → 中州韵引擎 → 中州韵引擎变体」可在内置引擎之外加载引擎提供 APK 或导入的 `.so`；内置引擎始终保留为默认与故障回退。切换方式、工作目录绑定、启动守卫与授权检查见 [中州韵引擎变体](./rime-engine-variants)。

### 能切换引擎但没有中文候选

API 探测通过只说明引擎接口可用，不检查方案内容。核对步骤见 [中州韵引擎变体](./rime-engine-variants#能切换引擎但没有中文候选)。

## 万象方案更新与高级设置

万象用户可在「设置首页 → 中州韵引擎 → 中州韵方案更新 → 万象更新」选择版本、通道、下载源与更新范围，并在高级设置中编辑常用参数。完整说明见 [中州韵方案更新](./rime-scheme-updates#万象方案更新与高级设置)。

## 自定义方案更新

其他 Rime 方案可在同一页的「自定义更新」中，从 HTTP(S) 链接或本地文件建立更新任务。任务格式、排除规则与限额见 [中州韵方案更新](./rime-scheme-updates#自定义方案更新)。

## 编辑器内预编辑

“编辑器内预编辑”可选“不显示”“编码”“候选预览”。“编码”模式中的光标按原始编码定位，显示用的拼音分隔符不会被算成新增编码。转换文字无法唯一对应编码位置时，光标恢复到引擎当前位置；“候选预览”用于显示预计上屏文字，不按预测词的位置改写编码。

## 方案与开关

语言键短按发独立 Shift，长按打开方案列表。状态区的互斥开关按组显示，方案列表不重复列开关。
方案菜单根据引擎的勾选状态标出当前方案，密码或西文输入的直接输入标记不会代替方案名称。
候选注释遵循方案配置；切换语言、方案会短暂显示提示。
中文空格标签为“中州韵（方案名）”，紧凑为“㞢”，ASCII 状态在中文界面显示“英文模式”。

状态区操作的方案开关按已部署 `default.yaml` 的 `switcher/save_options` 列表记忆，切换应用或重启输入引擎后由 Rime 恢复。互斥组选项会同时保存选中与取消选中的值。方案若为开关声明 `reset`，新会话仍优先使用该默认值；未列入记忆列表的开关只影响当前会话。修改记忆列表后需重新部署。

状态区 Rime 方案菜单的中英文切换项显示点击后进入的模式：当前中文时显示“英文模式”，当前英文时显示“中文模式”，与编码区切换提示使用同一文案。英文状态下，状态区的菜单入口也显示“英文模式”。该切换入口遵守同一记忆列表；将 `ascii_mode` 加入 `switcher/save_options` 后，菜单切到英文或切回中文都会保存，跨应用或重启时仍由 Rime 恢复，并保留方案 `reset` 的优先级。

跨应用或经过敏感输入时，方案和中英文状态采用 Rime 新会话的初始化结果；前端不会回放上一输入框的方案或临时西文状态。`switcher/fix_schema_list_order: true` 时，新会话从列表的首个有效方案开始；普通配置下由 Rime 恢复最近选择的方案。只有同应用前后两个输入框都允许普通学习、原会话仍可用时，才能复用引擎会话，保留当前状态而不重新执行方案的 `reset`。

例如，在文本框按 Shift 切到英文，进入密码框后再回到文本框，会先后创建敏感和普通新会话；方案若声明 `ascii_mode` 的 `reset: 0`，回到文本框时恢复中文。没有 reset 时，由 Rime 的已保存选项和初始值决定。密码、PIN、禁止个性化学习等边界双向隔离，不能把“同应用”理解成经过密码框后仍保持原会话。

### 输入类型（EVO 方案）

使用 librime-evo 引擎时，方案可以为不同双拼或形码声明 `input_types`。入口不在引擎设置页，而在「启用的输入方案」列表的当前方案行：按钮显示当前输入类型，点开按方案 `input_types/options` 的 `label` 列出选项。只有方案声明了 `input_types` 才显示按钮；只有当前引擎被识别为 librime-evo 时才可编辑，否则按钮置灰并提示“仅在使用 librime-evo 引擎时可用”。当前类型优先取 `reset`，没有时取 `enabled` 首项；`enabled` 缺失时视为方案声明的全部选项，`reset` 必须属于 `enabled`。

选择后应用只改写当前方案 `wanxiang.custom.yaml` 的 `input_types/enabled` 与 `input_types/reset` 两项，保留注释、键序、换行和其他补丁，使用原子写并在写入前后做结构化校验。写前会重新核对当前引擎仍是 EVO、当前工作目录与活动引擎绑定目录一致。当前正在运行的方案立即调用 `set_option(name, true)` 并重新部署；其他方案在下一次激活时由 `reset` 生效。保存成功但重新部署失败时只提示，不回滚已写入的类型；写入失败则提示“切换输入类型失败”且不改文件。选项完全来自方案，应用不另存本地状态。custom 的平铺子键只改对应字段；整组 `input_types` 按 Rime 规则替换整组，因此需要重新声明 `options`。

密码框默认不进入 Rime：按键直录给编辑器，不能切换输入法或使用候选。需要让密码框也能输入中文时，在「中州韵引擎 → 中州韵引擎设置」打开**允许在密码框中使用输入法**；开启后密码框与普通输入框一样使用当前方案、候选和中英文切换，但用户词学习、输入统计与语音输入仍保持关闭，敏感会话隔离也不因该开关取消。

Shift 按键由方案的 `ascii_composer` 处理，前端不会把每次按键造成的临时西文状态强制保存为长期偏好；它与按 `switcher/save_options` 保存的菜单切换入口各有作用。会话是否复用由 Android 前端的输入边界决定，新会话采用什么方案和模式由 Rime 决定。

## 标点与简繁转换

标点键的键面与长按弹出项保留布局、弹出预设中定义的文字。选择单字符标点时仍发送按键给 Rime，由方案的 `punctuator`、中英文状态及相关开关决定实际上屏内容；显示的句号或逗号不一定等于最终上屏字符。多字符文本及宏的行为继续由所选按键动作决定。

旧 Fcitx 的 `punctuation` 映射编辑、`chttrans` 配置页面及回调已移除。需要调整标点或简繁转换时，修改 Rime 方案的标点配置或转换器及 OpenCC 设置后部署；Rime 通用标点预设、OpenCC 数据与现有方案开关继续保留。旧布局中的 `transformPunctuation` 字段仍可读取，不再用旧 Fcitx 映射改写键面和弹出标签。

## 音节标签与模糊拼写

九键输入时，点选完整音节标签会按该音节筛选候选。方案若启用了 `en/eng` 等模糊拼写，点选 `shen` 可以保留通过该规则匹配的 `sheng`；`qi`、`pi` 等音节仅因九键编码相同而重码时，点选 `pi` 不会因此保留 `qi`。

`android-sdk-20261116-2` 加入九键字面标签修订；`android-sdk-20261120-1` 起继续调整：音节栏只在当前音节为九键数字输入时显示，字母输入本身已精确，不再弹出音节栏；已确认前缀后剩余的数字音节仍显示，混合输入两个方向都适用。存在 `derive/fuzz` 且当前位置适用九键字母映射时，完整音节栏只显示本音节拼写能匹配按键的标签：例如万象九键规则下 `9826` 显示 `zuan`，`948264` 显示 `zhuang`，不会把仅由模糊派生进入候选图的其他音节名放入完整音节栏。选中 `zuan` 后，方案允许的“转／专／装”和“转速／专属”模糊候选仍保留。没有 `derive/fuzz` 的方案维持原有补全、简拼标签和选中行为。正式 SDK 与消费该版本的输入法 Nightly 已发布，本次实际设备回归通过；固定版本和验证范围见[本次 SDK 消费记录](/maintainer/changes/2026-11-16-syllable-fuzzy-filter-fix#新版-sdk-消费与默认分支重写)。

模糊关系取决于方案中按顺序实际生效的 `derive`／`fuzz` 规则。前置变换、后续删除或编码变换都可能改变规则的结果；单独的普通变换不建立模糊关系。修改方案后需重新部署，并使用包含对应修订的引擎。内置引擎的现行版本见[引擎、插件与依赖更新](/maintainer/engine-update#两条链路)；已安装的旧版 APK 要更新到引用新 SDK 的输入法构建才会使用新引擎，修复范围与验证见[2026-11-16 音节筛选记录](/maintainer/changes/2026-11-16-syllable-fuzzy-filter-fix)。

## 候选手势与编码保护

按住候选后上滑可打开选字操作，下滑打开候选菜单。忘记词汇、注释和词频行为取决于方案与引擎支持。万象拼音方案（`wanxiang*` 且加载了 `super_sequence`）另有置顶、前移一位、后移一位、重置排序四项手动排序，按键来自方案的配置，见[候选窗增强](/features/candidate-window#万象拼音手动排序)。快速滑出候选范围会取消本次选择，见[候选指南](/features/candidate-window)。
候选更新期间，旧列表的点击和菜单操作会失效，不会选中新列表的相同序号。横向、展开和浮动候选使用相同的顺序与版本保护；文字相同的刷新保持画面稳定，展开列表仍会更新后续候选。
长按退格删空编码后会保护正文，抬手后再按可继续删正文；长按连删后上滑，在合成中只清编码，非合成时才清空输入框，见[退格键](/features/keys/backspace-key)。

## 引擎来源与更新

内置引擎使用 `SandyYuR/librime` 的 `zhongzhou` 定制源码，由该仓库独立构建并发布 Android SDK。输入法固定引用经过验证的 SDK 版本及摘要；当前构建不再使用 prebuilder/prebuilt。用户选择的运行时变体另按其列表摘要、探测结果和提供 APK 签名识别，不会改写内置 SDK 锁。
版本和定制来源以对应 APK 的源码与元数据为准。插件和依赖固定到明确版本，不随上游自动更新；升级步骤、组件来源和回退见[引擎、插件与依赖更新](/maintainer/engine-update)。方案文件仍按方案自己的说明更新并部署。
此前更新的固定提交、数量与验证保留在[2026-10-21 引擎记录](/maintainer/history/DIRECT_RIME_ENGINE_UPDATE_2026-10-21)。

## 输入与学习

按键、候选操作和会话管理由单一 owner 串行处理；同应用普通编辑器可复用会话，跨应用与敏感输入隔离。
用户词库通过 Rime 学习和同步。多个输入法不要同时打开同一个外部工作库。
键盘显示后，输入法会在后台低优先级预读当前方案的语言模型和主词典等只读文件，开始输入、隐藏键盘或状态失效时取消；低内存、省电或设备过热时跳过。预热只影响系统文件缓存，不改变候选、学习或部署结果，实现与实测见[直连架构](/maintainer/implementation/direct-rime-architecture)。
Rime 引擎默认只向实时日志输出 ERROR／FATAL。排查部署、词典编译或插件加载时，可在「设置 → 高级 → 开发者」打开 **Rime 引擎日志**，让引擎同时输出 INFO／WARNING；该开关在引擎初始化时读取，切换后需重启应用生效，见[用户手册](/manual/DIRECT_RIME_USER_GUIDE_zh-CN#保存日志与卡顿反馈)。
实测数据与边界见[历史交付记录](/maintainer/history/DIRECT_RIME_RELEASE_READY_2026-10-21)。
