# 备份与恢复

本页说明本批修复后的流程，版本与合入状态见[本批合入准备](../maintainer/review-2026-10.md)。旧版可能只提供明文 ZIP。

在应用的“数据与备份”页面导出、导入完整用户数据。换手机、换包名、换签名或卸载前，先把备份保存到应用目录以外。

## 导出格式

| 格式 | 用途 |
| --- | --- |
| 默认的加密 `.fcbak` | 保存完整备份，导入时输入导出时设置的密码。 |
| 明文 ZIP | 在导出对话框中明确选择，用于兼容旧版或上游版本；文件内容没有加密。 |

密码不要求复杂度，但不能为空，并需再次输入确认。应用不会保存密码，也无法找回。
这是备份文件的密码，与[局域网编辑器](online-editor.md)的六位配对码无关。

完整备份可能包含用户词库、布局、主题、剪贴板历史、目录路径和同步设置。
Android 系统自动备份仅保留部分设置界面外观，不能替代手动完整备份。

## 导入流程

1. 先为当前数据导出一份备份。
2. 选择 `.fcbak` 或兼容 ZIP；加密文件输入对应密码。
3. 等待校验，核对恢复目标和替换范围，再确认恢复。
4. 恢复时输入法暂时停止，应用通过独立恢复页面完成替换；结束后重新打开并核对方案、用户词库、布局与主题。

加密文件认证完成前不会解析 ZIP 或替换现有数据；认证通过后仍会检查压缩包、数据库、偏好和目标目录。
不要把公共存储根目录或混有其他用途文件的父目录选作恢复目标。

## 中断、冲突与外部存储

恢复记录会在进程退出后用于继续清理或回滚。再次打开出现恢复页面时，先按提示重试；有外部存储时，确认原来的卷和目录已经可用。
发生目录冲突会保留原数据和导入数据，诊断文件只提供路径与错误信息。
保留原数据等待恢复时，不要清除应用数据或手动删除不确定用途的恢复目录。

进程中断恢复已通过相应测试，不代表已经验证物理断电、文件系统损坏或真实存储卷拔插。

## 不同备份的区别

- Rime 同步用于交换用户词典等方案数据，不是完整应用备份。
- 布局／主题二维码用于分享单份配置，不包含全部应用数据。
- 系统自动备份只含外观白名单，不包含主偏好、剪贴板、同步凭据和 Rime 文件。

开发与兼容性细节见[加密备份格式](../maintainer/implementation/protected-backup-format.md)和[整包恢复事务](../maintainer/implementation/user-data-restore.md)。
