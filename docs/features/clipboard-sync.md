# 剪贴板同步（内置）

主程序**内置**剪贴板同步能力，与桌面端及其他设备互通，使用同步功能无需另装插件。

## 兼容的同步服务

主程序作为客户端，可连接以下开源剪贴板同步服务的任意一个：

| 服务 | 状态 |
|------|------|
| **[SyncClipboard](https://github.com/Jeric-X/SyncClipboard)** | 已验证 |
| **Oneclip** | 协议兼容 |
| **[ClipCascade](https://github.com/Sathvik-Rao/ClipCascade)** | 协议兼容 |

工作方式：在服务端部署任一同步服务（自建 / 公网 / 局域网）→ 在应用内填服务地址、端口、认证信息 → 复制 / 粘贴内容经服务在多端互通。推荐使用 `https://` / `wss://`；明文 HTTP 只应在完全可信的局域网临时使用。

## 应用内剪贴板

无论是否启用外部同步，应用内剪贴板都提供：

- 历史记录、固定（pin）、删除、搜索
- **在「全部」页中隐藏收藏项**：在 **设置 → 便捷功能 → 剪贴板** 开启，默认关闭。开启后，键盘剪贴板和搜索面板的「全部」都只列出未收藏条目；在「全部」页批量删除也会保留隐藏的收藏。收藏内容仍可在「收藏」查看，其他分类的筛选规则不变；取消收藏后，条目会重新出现在「全部」。
- **历史实时搜索**：进入剪贴板窗口后点搜索按钮，在键盘上方打开紧凑的浮动面板。上方复用剪贴板双列卡片，下方固定搜索框、关闭按钮和全部／收藏／本地／媒体／其他设备分组；初始选中刚才打开的分组，空查询显示该分组的全部历史，输入时只筛选当前分组。结果按原有顺序分页加载，可滚动查看全部匹配条目；点击文本卡片关闭面板并粘贴，媒体条目和长按菜单沿用普通剪贴板操作。搜索只在本机匹配（SQL 筛选 + 防抖），查询不会输入原应用；关闭、切换输入框或隐藏键盘会结束面板。
- 搜索面板的卡片、分组、图标与撤销提示统一跟随设置界面的外观配色，包括浅深色、手动色板、对比度、纯黑及已开启的键盘取色。分组选项在空间不足时整颗按钮换行，保持完整可点。
- 剪贴板搜索和文本编辑面板中的编码区显示在弹框上层，输入、退格和换行时弹框不随编码区移动；当前文本框保留正常的编辑光标闪烁。
- 面板显示后，从工具栏展开普通剪贴板并返回键盘时，搜索内容和本地输入连接继续保留，面板不会因键盘重新布局短暂隐藏。
- 搜索媒体卡片的预览留白、缺失图片占位与整张卡片使用一致底色。键盘里的普通剪贴板页继续使用键盘主题和原有 30 dp 分组高度；搜索弹框的分组保留 48 dp 触摸高度，空间不足时完整换行。
- 短条目的点击区域更大，置顶标记更清晰。条目编辑和工具栏剪贴板长按编辑使用键盘上方的浮动面板，直接向面板输入，不再切换到独立编辑页面；关闭后回到原输入连接。窄屏或大字号时操作按钮按完整按钮换行；复制在保存成功后执行，保存失败保留草稿，取消不保存未确认的编辑。
- **文本条目分词选择**：对单个文本条目执行“分词”（英文界面为 Split words），拆成词 / 字符片段后点选、组合发送到输入框
- 快捷磁贴（Quick Settings tile）可真正启动 / 停止同步服务

## 入口

- 设置：**应用主页 → 便捷功能 → 剪贴板**（远端同步设置在同页进入）
- 键盘内：**Kawaii Bar 的剪贴板按钮**（或状态区同名入口）打开剪贴板窗口

## 文本条目分词选择

1. 在剪贴板窗口中打开某个文本条目的操作菜单
2. 选择 **分词**（英文界面为 Split words）
3. 在分词结果中点选或拖动选择多个 token，也可使用全选、反选或取消选择
4. 点击 **发送**（英文界面为 Send）将选中的片段组合后发送到当前输入框

## 稳定性与隐私（本版持续加固）

- **release 版日志不再写入剪贴板原文**（语音原文同样）；
- 传输按上限**流式读取**、解码前先过滤尺寸；接收过滤缓存化，不逐条重建；
- 前台服务使用 `dataSync` 类型并空闲降频，后台同步不再"不停摆"；前台状态更新幂等，不重复投递通知；
- 网络栈超时 / 取消语义完善，PBKDF2 参数规范；同步状态使用专用存储并在锁内序列化；
- 历史增量全部导入、游标不再跳过；存储路径解码对裸 `%` 与畸形编码健壮；
- 长文本分词设上限，分词任务跟随视图生命周期取消。

## 已知限制

- 后台被系统杀掉时同步会暂停（Android 系统行为）——国产 ROM 请为本应用开启[自启动与后台权限](/troubleshooting/oem-startup)
- Android 10+ 限制后台读取系统剪贴板；作为默认输入法使用时捕获通常更可靠，必要时用同步通知里的「抓取并同步」做一次前台捕获

## 同步行为与兼容条件

- 新地址默认使用 HTTPS；已有显式 HTTP 地址保留兼容。HTTPS 重定向不能把凭据带到降级后的明文地址。
- 主动暂停或关闭同步会真正停止服务，排队的启动或重连不会自行重新开启它。
- 剪贴板编辑确认后先完成数据库写入，再关闭页面；保存失败可重试，已删除的条目不会被旧保存任务重新创建。
- ClearURLs 规则随应用固定打包，过滤在后台按顺序处理；规则预算耗尽时保留原始文本。
- ClipCascade 在接收完整消息之前检查帧和分片预算。单条载荷上限随应用最大堆调整（约为最大堆的 1/32，最多 32 MiB），超过预算的消息会拒绝。

ClipCascade 服务端应支持未压缩消息，WebSocket 地址需直接返回 HTTP 101。
明文 WS 经 SOCKS 代理不受支持；WSS 经 SOCKS 和明文 WS 经 HTTP 代理保留相应路径。
完整兼容条件见[接收限额说明](../maintainer/implementation/clipcascade-receive-limits.md)。

### 消息顺序与接收过载

同一连接收到的远端消息按顺序处理，并限制排队消息的总字节数。超过接收预算会报告过载，不会无限积压内存。
这项限制属于远端剪贴板传输，与按键、提交文字的有序输入通道不同。
