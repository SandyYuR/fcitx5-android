# 外部语音输入

在语音设置的“首选语音输入”中选择支持本项目 AIDL 接口的外部识别应用。

也可以不装任何 APK，直接导入一个 JS 语音插件：这类插件跑在输入法进程内的 QuickJS 里，由宿主提供录音、WebSocket、HTTPS 与密钥托管。用法与开发接口见 [JS 语音插件](./voice-input-js.md)。
输入法负责录音并把音频交给提供方，识别结果回到当前输入框。是否联网、使用何种模型和账号由所选提供方决定。

## 使用与排查

1. 安装兼容的外部语音识别应用，完成它自己的必要设置。
2. 在中州鹅选择首选语音输入，授予录音权限，再从键盘语音入口开始识别。
3. 连接失败时检查提供方是否可用、是否支持本项目协议，以及其后台运行限制；普通系统语音应用不一定实现相同协议。

Rime 输入引擎已经内置。外部语音识别提供方使用 Android 接口，独立于 Rime 的方案和词典。

## 不装 APK 的方式

内置与可导入的 JS 插件（千问、豆包等）走同一套会话与结果回填，入口在**设置 → 便利功能 → 语音输入 → 语音插件设置**。导入、覆盖升级、移除与插件接口的完整说明见 [JS 语音插件](./voice-input-js.md)。

## 会话与输入框

主程序按语音请求和输入框会话核对回调。停止识别、切换输入框或旧连接失效后，迟到结果不会被当作新请求直接提交。
同一输入框的正常 `restartInput` 可以保留恢复资格；最终结果只接受一次。

## 可选浮窗回退

正常路径使用 AIDL。只有正常绑定失败时，代码才尝试兼容的 `FloatingService`。
提供方必须声明支持会话令牌，并在结果中原样回传本次令牌，主程序才启用该可选回退。

不支持令牌的旧浮窗回退不会直接上屏；此时会显示连接失败，可重新开启或更新提供方。
正常 AIDL 提供方不需要为此添加浮窗声明。

纯云端协议、想快速换服务商时，用 [JS 语音插件](./voice-input-js.md) 通常比做一个 AIDL APK 更省事；需要本地模型或厂商 SDK 时仍应走 AIDL。

第三方实现方式见代码仓库的[中文 AIDL 接入协议](https://github.com/SandyYuR/fcitx5-android/blob/fx-rime-only/ASR_VOICE_INPUT_AIDL_INTEGRATION.md)。本批协议补充在[代码 PR #13](https://github.com/SandyYuR/fcitx5-android/pull/13)中交付。
