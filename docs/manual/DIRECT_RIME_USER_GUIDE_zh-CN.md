# 中州鹅用户手册（直连 Rime 版）

本手册描述当前维护中的直连版；旧 APK 的差异请结合对应版本说明阅读。应用名 **中州鹅**，包名 **`org.fcitx.fcitx5.android.fx.rime`**。
本版直接使用 Rime 引擎，并提供完整键盘、候选、布局编辑器、主题和设置界面。
Rime 方案决定输入规则与词典；键盘布局决定屏幕按键和手势，两者分别设置。

## 安装与首次输入

1. 从 Releases 下载“中州鹅”Nightly，或从成功的 `Commit CI` 获取签名 Release 产物；按设备 ABI 选择安装包，
   可选 ABI、资产与产物命名见[安装与升级](/guide/installation#下载主应用)。
   `Direct Rime CI` 只在手动运行完整诊断时生成完整界面调试包 `direct-rime-frontend-arm64-debug`；
   `direct-rime-arm64-debug` 仅为引擎诊断工具。
2. 安装后，在 Android 系统设置中启用并选择“中州鹅”。Debug 包名为 `org.fcitx.fcitx5.android.fx.rime.debug`，可与 Release 共存；两者数据独立，Debug 也要自行导入并部署方案。
3. 打开应用，进入「设置首页 → 中州韵引擎 → 中州韵引擎设置」，准备下面所述的 Rime 用户文件并部署。

APK 不内置中文方案、完整词典或万象模型，只包含 Rime 通用标点、符号与按键绑定预设。
初次安装时键盘能弹出但没有中文候选，通常是还没导入方案。
覆盖升级需要同包名、同签名；本地签名包和 CI 包不保证能够互相覆盖。

## 引擎版本与方案更新

APK 内置固定版本的 librime、Lua 运行时和引擎插件；重新启动应用、部署方案或检查更新都不会自动升级这些组件。安装引用新版引擎 SDK 的输入法 APK 后才会使用新引擎。

万象等方案的 YAML、词典、Lua 脚本和模型由方案自己维护，按方案说明更新文件并部署。方案脚本、Lua 运行时与 librime-lua 插件是不同层次，升级其中一项不会自动更新另外两项。升级前保留自定义补丁和用户数据备份。

确切的内置引擎版本可查看对应 APK 源码中的 `native/rime-sdk.lock.json` 和发布说明；外部引擎以变体列表的摘要和运行时版本为准。维护者构建、依赖升级及回退步骤见[引擎、插件与依赖更新](../maintainer/engine-update.md)。

开发者可在 Windows 本机修改引擎并生成独立 Debug 包，操作见[本地引擎开发](../maintainer/local-engine-development.md)。这类开发包以构建时保存的 `sdk-manifest.json` 源树和摘要为准，不改变日用发行包的版本锁。

### 中州韵引擎变体

「设置首页 → 中州韵引擎 → 中州韵引擎变体」可以在三种来源之间切换：

- 随中州鹅 APK 静态打包的 `SandyYuR/librime`，始终保留为默认引擎和故障回退；
- 已安装且实现 `org.rime.plugin.MANIFEST` 协议的引擎提供 APK；
- 用户导入、由中州鹅保管的自包含 Android `.so`。

每个外部引擎都要绑定一个已经在“数据目录管理”中登记的 Rime 工作目录。切换时会暂时停止输入，清理当前会话，在同一输入法进程中加载目标引擎并执行完整部署；页面以“正在切换并部署…”和不定进度条显示这段过程，不会用没有依据的百分比。加载或部署失败时会原地恢复先前引擎；只有原生引擎崩溃、停止超时或回退也失败时，启动守卫才结束当前进程并在下次启动继续回退。外部引擎正在使用时，旧“数据目录管理”不能直接切换目录，“导入方案 ZIP”也不会另建并切到新目录；请在「中州韵引擎变体」页改绑活动引擎。被任一外部引擎或内置回退设置引用的目录不能重命名或删除，应先修改相应绑定。不要让两个输入法同时打开同一个外部工作库。删除导入引擎只删除中州鹅保管的二进制及执行副本，不删除所绑定目录、方案、词典或用户数据。首次解锁前固定使用内置引擎。

每次准备使用外部引擎时都会先保存启动守卫，成功初始化、部署并刷新方案后才清除；显式切换或改绑还会完整部署。普通切换会保留已经清理的先前引擎槽，目标可恢复失败时直接切回；启动中发生原生崩溃时，下一次进程仍会恢复存在的先前引擎，最坏回到内置引擎。这个守卫减少连续崩溃循环，不替代用户数据备份。

导入 `.so` 分为两次确认。应用先在不执行文件的情况下检查 ELF 类型、当前进程 ABI、16 KiB 加载段对齐、可写可执行段、可执行栈、文本重定位、RPATH/RUNPATH、动态依赖及 `rime_get_api` 入口。用户确认后，文件才会在一次性 Android isolated UID 进程中执行，以核对 `RimeApi` 结构、必需函数和 librime 版本；该进程不继承应用 UID 和权限，只取得只读文件描述符，并把同一载荷复制到自己创建、封印且不可再写的内存文件后加载，其崩溃、取消或超时不会带倒输入法。若旧设备内核或系统安全策略不支持安全 memfd，应用会明确拒绝探测，不会退回较弱的同 UID 或可写共享内存方案。这里仅验证 API 兼容，不部署目标目录，也不能证明某套方案、词典、Lua 或模型可用。通过探测、选择工作目录并再次确认完整信任后，文件才会被导入。原生代码最终仍在输入法主进程中运行，能够接触输入内容、Rime 数据和输入法权限，因此只能导入可信来源。若页面因主题、语言、旋转或系统配置重建，当前确认会取消、该页面实例的暂存文件会删除，需要重新选择文件。

普通 `.so` 没有 Rime 规定的“引擎名称、作者、仓库、说明、图标”元数据标准。应用可静态读到 ELF 架构、SONAME、Build ID、依赖和摘要，执行 Rime API 后可读到 librime 版本；列表名称由用户在导入时填写。`.rimeengine` 不是 Rime 或 librime 的既有标准格式，本功能没有要求这种扩展名。

引擎提供 APK 协议也不是 Rime 上游标准。中州鹅发现提供者后仍执行同样的 ELF 与运行时检查，并把授权绑定到 APK 包名、签名证书、引擎载荷 SHA-256 和 SONAME，同时要求受支持的协议元数据。真正启动时先把载荷复制为中州鹅管理、按摘要命名的只读执行快照，再复查当前安装包的证书和元数据；APK 在复制期间更新、换签或替换载荷会使本次启动失败，授权字段变化时还要重新授权，不会直接从提供 APK 的可变路径执行。正在使用或保留为崩溃回退的 provider 不能就地覆盖授权；请先切到内置引擎，再授权新版本。使用每次 CI 临时证书生成的测试 APK 时，下一次产物通常不能覆盖升级；长期使用应由提供仓库配置固定签名。

### 部分部署失败时的降级

使用 librime-evo 引擎和部分方案时，部署日志可能仍显示 failure，例如方案缺少只被间接引用的包装词典。只要当前工作目录已生成 `build/default.yaml`、引擎能列出方案、当前方案编译出的 `build/<schema>.schema.yaml` 非空，并且当前方案主词典的 `build/<dict>.table.bin` 与主 prism 的 `build/<prism>.prism.bin` 都存在且非空，中州鹅会保留失败记录但允许继续输入；任一条件不满足时仍会失败关闭。

降级不表示方案完整、所有词典已编译或语言模型已验证。日志、失败通知和缺失文件保持原样，应用不会自动补文件；主词典、Lua 或模型缺失时仍可能没有候选，必须实际输入并上屏确认。当前方案优先取活动会话，没有会话时按 `switcher/fix_schema_list_order` 和 `user.yaml` 的 `previously_selected_schema` 选择。

### 输入类型（EVO 方案）

使用 librime-evo 引擎时，方案可以声明 `input_types`。入口在「启用的输入方案」列表的当前方案行：按钮显示当前类型，点开后按方案 `input_types/options` 的 `label` 列出选项。只有方案声明了 `input_types` 才显示；只有当前引擎是 librime-evo 时才可编辑，否则置灰并提示“仅在使用 librime-evo 引擎时可用”。当前类型优先取 `reset`，没有时取 `enabled` 首项；`enabled` 缺失时视为方案声明的全部选项。

选择后只改写当前方案的 `*.custom.yaml`（万象方案为 `wanxiang.custom.yaml`）中的 `input_types/enabled` 和 `input_types/reset`，保留注释、键序、换行和其他补丁，并原子写入，其它补丁与键保持不变。写前会重新核对当前引擎与工作目录；当前方案立即调用 `set_option` 并重新部署，其他方案在下次激活时由 `reset` 生效。保存成功但部署失败时只提示，不回滚类型；写入失败时提示“切换输入类型失败”且不改文件。切换后应实际输入验证。

## 导入方案与万象

### 从方案 ZIP 导入

进入“导入 Rime 方案”，选择方案 ZIP。压缩包根目录应直接包含 `default.yaml`
或 `default.custom.yaml`，以及方案、词典、Lua 等依赖文件，不能只放一个仓库外层目录。
选择 ZIP 后选择导入到应用目录或可访问的外部目录；未具备外部访问权限时，可改用应用目录。导入完成后按页面提示部署，原目录仍可在数据目录管理中切回。
压缩包上限为 512 MiB。方案 ZIP 与“完整用户数据备份 ZIP”用途不同。

导入页用状态卡片显示读取、检查和导入阶段，实际开始导入时列出目标目录；完成结果留在页面中，错误可展开查看详情。已有的目录选择、权限申请和方案校验仍需完成。

### 手动放置方案

在「中州韵引擎设置」打开当前用户数据目录。默认位于应用外部文件目录的 `data/rime`，
具体以当前数据目录设置为准。将方案及完整依赖放入该目录，在 `default.custom.yaml` 指定方案：

```yaml
patch:
  schema_list:
    - schema: your_schema
```

将 `your_schema` 替换为方案实际的 `schema_id`，然后在「中州韵引擎设置」执行部署。
修改 YAML、词典或 Lua 后一般需要重新部署。部署期间等待“正在部署”消失后再输入。
重新部署会卸载并重建 Rime 运行环境，重新读取 Lua 模块、方案列表及开关；完成后恢复可用状态。
是否生效应以新方案、开关和实际候选为准，按钮闪烁的时长不能单独证明部署结果。

### 万象更新与高级设置

**万象更新与高级设置仅适用于使用万象方案的用户。** 其他方案可使用同一页的「自定义更新」，或遵循方案自己的更新方式。

进入「设置首页 → 中州韵引擎 → 中州韵方案更新」，选择「万象更新」，其下方为「自定义更新」。页面显示当前 Rime 工作目录，下载及高级设置均作用于此目录；需要更换目标时，先在「中州韵引擎设置」切换数据目录。目录读取失败时，恢复存储访问后可点击“重新读取工作目录”，读取成功前不能开始新更新。已排队任务的目标保持不变，任务尚未报告目标时不会用后来切换的目录代替显示。APK 本身仍不预装中文方案或模型。

先选择更新范围，再核对 Base / Pro / Lite / Pure 版本；Pro 的方案或词库更新还需选择匹配的辅助码。正式／预览通道用于方案包，词库使用滚动更新资源，模型使用 LTS 资源。方案、词库和模型可选择 CNB 或 GitHub；附加词库固定来自上游数据仓库。

| 更新范围 | 下载内容 |
| --- | --- |
| 全量更新 | 方案、词库、语言模型，以及已勾选的附加词库；包含较大的模型文件 |
| 仅方案 | 方案配置与相关文件；不下载已勾选的附加词库 |
| 仅词库 | 当前版本词库，以及已勾选的附加词库 |
| 仅模型 | `wanxiang-lts-zh-hans.gram`；不下载方案、词库或附加词库 |
| 仅附加词库 | 只下载勾选项；至少选择一项才能开始 |

“附加词库”可刷新目录并选择所需条目。Lite 按上游固定字符映射处理声调，`ü` 及其声调形式转换为 `v`，保留 `ê` 等映射以外的字符；Pro 会按当前辅助码字表加工。仅更新 Pro 附加词库时，需要当前目录已有匹配的 `dicts/zi.pro.dict.yaml`。下载后还需在主词典的 `import_tables` 中引用相应词库，下载本身不会自动启用它。

“防覆盖保护”可编辑相对路径的正则规则，默认保护自定义补丁、个人短语、简码和手动排序数据等。应用同时保留用户数据库和同步数据；规则不是完整备份，更新前仍应保留自己的备份。GitHub Token 为可选项，使用设备密钥加密保存，仅发送到受支持的上游 GitHub API；配置成功不等于网络连接已验证，可单独检查连接。

点击“下载并更新”后，资源先下载到暂存区，完整准备好后再应用并重新部署。离开页面后后台任务可继续；写入阶段等待完成。下载期间切换工作目录会阻止旧任务写入新目录，应用或部署失败会尝试恢复被替换文件。失败结果及详情会保留在页面中。如果所选文件全部受到保护，页面显示“没有需要写入的文件”，这表示本次未写入或重新部署，不代表安装了更新。

下载链接返回 HTTP 404 时，首次请求后最多再重试三次，仍然缺失则跳过该文件，其余可用内容照常安装和部署。页面只简要说明哪些组件因 CNB 或 GitHub 仓库资源暂不可用而跳过，完成后说明其余内容已部署；不要求用户处理仓库问题。后续失败或重新打开页面仍能查看跳过清单。没有可部署资源时显示“本次未部署”；其他下载或文件校验错误不会被当作缺失资源跳过。

进度条表示**当前文件**的下载比例，旁边显示文件名、已下载大小／总大小和可用的下载速度。服务器未给出可靠总大小时不显示百分比，仅显示已下载大小与“总大小未知”。切换下一个文件时重新计数；解压、检查和部署改为阶段提示，不能把一个文件的 100% 当作整个更新已完成。断网等系统暂停会保留分片，恢复后在服务器支持的情况下续传；主动点击取消会清理本次缓存。

“高级设置”提供常用参数，以及按文件、分组浏览的配置字段。打开页面只读取现有配置，不自动部署；缺少部署文件时可显式点击“修复部署”。默认补丁模式写入 `.custom.yaml`，直写模式修改源文件，后续方案更新可能替换直写内容。

修改先保留为草稿，点击“保存并重新部署”才写入；外部配置或工作目录变化时会阻止旧草稿覆盖，需重新加载后处理。短语／简码关联取消勾选会明确禁用相应字典引用，重新勾选可恢复关联；通过“添加配置项”保存的自定义字段会继续显示，便于再次编辑。列表、映射及 YAML 编辑入口保留，复杂配置应结合所装万象版本的说明使用。

移除字段覆盖时会保留旁边的自定义项；无法安全拆分的多层父补丁、编译引用或列表内部覆盖会提示改为编辑整个父字段，并保留原草稿。若没有独立的短语／简码方案文件，常用设置按主方案实际使用的词库显示；多个主方案使用不同词库时会说明当前词库的归属，未关联的其他词库不会被一并清空。

### 自定义方案更新

在同一页的「自定义更新」中添加任务，填写名称、下载链接或选择本地文件。可解压常见 ZIP/TAR 包，也可直接复制文件；相对子目录每行一个，`.` 表示当前工作目录。默认排除个人补丁、短语和调频文件，规则可编辑；用户词典与运行状态始终保留。

勾选任务后可批量执行，或单独执行某项。整个批次先准备资源，再统一部署；失败不会留下前半套方案。完整路径可展开查看，排队任务继续显示开始时的目标。支持格式、容量限制、规则与外壳目录处理见[自定义方案更新](/features/rime-scheme-updates#自定义方案更新)。

### 万象 base 配置示例

从 [万象官方仓库](https://github.com/amzxyz/rime-wanxiang)准备 **base / 全拼**版本，
按上游说明安装它依赖的词典、Lua 和语言模型。
需要相应功能时，在所装方案支持的开关中开启“上下文调频”“简码”或选择“小字集”；开关名称与模型文件以对应万象版本的说明为准，这些是可选配置示例。
“简码开启”与“使用双拼”是不同的选项，不需要为了开启简码改成双拼。

候选注释由方案自身的开关和过滤器决定。应用显示 Rime 提供的注释，
不额外把候选编码拼在后面。注释不符合预期时先确认正在使用的方案与开关，
再核对 Lua、配置补丁和部署日志。

日常方案升级请遵循万象自己的说明，并保留 `*.custom.yaml`、用户词库和手动排序数据。
本项目的性能测试使用固定官方夹具和新用户库，不能替代个人长期词频库的实机体验。

## 切换语言、方案和功能开关

- 语言键短按发送独立 Shift，中英文切换行为由方案的 `ascii_composer` 决定。
- 长按键盘语言键或使用“Rime 方案选单”切换方案；工具栏语言按钮长按可打开 Android 输入法选择器。
- 语言键与工具栏语言按钮的图标随中英状态切换：中文态显示「中/En」，ASCII 态显示「En/中」。可分别替换的图标主题槽位为工具栏 `toolbar.language_switch` / `toolbar.language_switch_ascii`、键面 `keys.language` / `keys.language_ascii`；按钮编辑里另有「ASCII 状态图标」可单独选择。
- 展开状态区可操作方案功能开关。二态按钮显示当前状态及目标状态；互斥选项按组显示，点开后选择。
- 状态区 Rime 方案菜单中的中英文切换项显示目标模式：当前中文时显示“英文模式”，当前英文时显示“中文模式”，点击后切到所显示的模式。
- 切换中英文时编码区短暂显示“英文模式”或“中文模式”；切换方案时显示方案名。
  提示会自动消失，继续打字时让出编码区，切换输入框后不延续旧提示。
- 空格键在中文界面显示“中州韵（方案名）”，其他语言显示“Rime (方案名)”；
  紧凑中文标记为“㞢”。英文状态名称在中文界面显示“英文模式”。

方案开关是否跨会话保留，由已部署 `default.yaml` 的 `switcher/save_options` 决定，可通过 `default.custom.yaml` 配置后重新部署。列表内的二态开关和互斥选项在状态区调整后会被记住，切换应用或重启输入引擎时恢复；未列入的开关只作用于当前会话。方案在 `switches` 中声明的 `reset` 仍优先于记忆值，因此固定重置的开关会在新会话恢复到方案指定状态。

菜单的中英文切换也遵守上述规则。要跨会话记住菜单中的语言选择，需将 `ascii_mode` 加入 `switcher/save_options`；切到英文与切回中文都会保存相应值。未加入列表时，菜单切换只改变当前会话。

跨应用或经过敏感输入时，方案和中英文状态直接采用 Rime 新会话的初始化结果，前端不会把上一输入框的状态再次写回。设置 `switcher/fix_schema_list_order: true` 时，新会话从列表的首个有效方案开始；普通配置下由 Rime 恢复最近选择的方案。同应用前后两个输入框都允许普通学习、原会话仍可用时可以复用，切换输入框不会重新执行方案的 `reset`。正在输入时的临时西文状态也不会被前端当作跨会话偏好回放。

从文本框进入密码、PIN 或禁止个性化学习的输入框，再回到文本框，也会新建会话。此前按 Shift 切成英文不保证跨越这一边界后仍为英文：方案有 `ascii_mode` 的 `reset: 0` 时恢复中文，没有 reset 时由 Rime 的保存值或初始值决定。菜单语言切换按记忆列表保存，Shift 的临时模式变化则交给方案的 `ascii_composer`，前端不强制保存每一次变化。

标点键与长按弹出项按布局原文显示，单字符标点交给 Rime 的 `punctuator` 处理；键面文字与实际上屏字符可能不同。旧 Fcitx 标点映射及简繁转换设置页已移除；标点和简繁需求在 Rime 方案内配置，Rime 通用预设与 OpenCC 继续可用，见[标点与简繁转换](/features/rime-enhancements#标点与简繁转换)。

## 设置入口

设置首页的「中州韵引擎」分栏位于「日常调整」之前，包含「中州韵引擎设置」「中州韵引擎变体」「中州韵方案更新」三个入口。引擎设置页提供启用的输入方案、编辑器内预编辑、用户数据目录、数据目录管理、导入 Rime 方案 ZIP、重新部署、同步用户词典和页尾的密码框开关；引擎变体管理外部引擎；方案更新页提供万象更新与自定义更新。
候选栏和候选窗口属于界面设置，仍分别提供调整入口。
“编辑器内预编辑”中的“编码”支持按原始编码定位光标，显示分隔符不会被当作编码字符；无法确定对应位置的转换文字会恢复引擎光标。“候选预览”不按预测词位置修改编码。候选更新时，旧候选的点击不会作用于新列表的同一序号。
重复的“全局选项”、固定引擎的“附加组件”列表和旧快捷键隐藏开关已移除。

设置首页的搜索框支持名称、别名及拼音。可搜索“主题”“布局”“字体”“候选”“备份”等，
跳转到对应设置页。开发者页中的引擎重启操作名为“重启输入引擎”。

## 数据目录、部署与同步

可在数据目录管理中创建和切换多个目录。内部目录保存在应用自己的数据位置；
注册外部目录只记录位置，不自动搬移原文件。删除外部目录条目只解除注册。

外部目录需可被应用直接读写：Android 11 及以上通常需“所有文件访问”，
Android 6–9 需存储权限；Android 10 优先使用应用目录。云盘文档提供方不能当作原生文件路径。

部署将方案源文件生成可运行数据；Rime 用户词典同步用于交换学习数据；
应用完整备份还包含布局、主题、偏好和剪贴板等。三者不能互相替代。
用户词典同步等待实际完成，失败会返回错误；同步及备份保存的维护阶段会暂停引擎输入。
同步入口会显示失败原因而不应崩溃。`.temp.userdb` 属于恢复流程的临时库，修复后的引擎同步会跳过；不要把删除普通 `.userdb`、`LOCK` 或用户词库当作同步修复手段。引擎 SDK 与应用侧修复的状态见[设备问题复核](../maintainer/changes/2026-11-06-device-fixes.md)。

同步合并已有词典快照、恢复词库或升级旧格式时会创建这个临时目录，包括合并本机此前的快照。正常退出会清理；进程被终止、数据库打开或删除失败可能留下它。仅凭残留目录不能判断方案损坏，也无法确定是哪次操作留下的。

### 多个 Rime 输入法共存

每个输入法使用独立的工作目录。不要让两个仍在运行的输入法同时打开同一外部目录中的
`.userdb` 或上下文学习库。LevelDB 对工作库加独占锁，冲突时可能出现以前学过的词和
新学词都不进入候选；它不一定意味着词库丢失。关闭键盘或划掉后台页面通常不会结束输入法进程。

若已共用目录并发生此现象，在系统应用管理中强行停止其他使用者，再强行停止并重新打开
中州鹅测试。2026-10-19 的用户反馈已确认这样恢复了用户词，不需要修改引擎或清空词库。
后续将工作目录分开，通过 Rime 的同步目录和各自同步 ID 交换用户词典。
迁移前先备份，停止所有使用该工作库的输入法后再复制文件；不要删除 `LOCK` 文件来绕过占用。

## 键盘、布局与宏

在“键盘”中调整高度、分体、单手、浮动、按键反馈和工具栏；候选栏与候选窗口在“输入与候选”中分别设置。
自动填充建议占住工具栏时，最左侧按钮换成返回箭头，点击收起本次建议，换输入框后恢复，见[内嵌自动填充建议](../features/kawaii-bar.md#内嵌自动填充建议)。
进入“键盘布局自定义”编辑布局，建议先复制布局并导出备份，再更改按键和宏。

布局可包含主键盘、数字层、符号层和方案/子模式的覆盖。
“键盘 → 键盘布局自定义 → 数字键盘布局”默认为“自动（跟随键盘布局）”：数字、电话和 PIN 输入框优先使用当前布局文件里的数字层（如 `__layer__:数字`、独立的「数字」条目或 `123` 等别名），没有时回落到内置数字键盘；也可强制选“内置数字键盘”或指定某个条目。更换成套主题后数字键盘随新布局切换。子布局下拉框同样列出这类层条目，显示为「层：数字」，可直接预览和编辑，见[层子布局与数字键盘](../features/editor/layout-editor.md#层子布局与数字键盘)。
按键可分别设置点击、长按、上滑和下滑动作；空格、退格等功能键有各自的手势规则。

需要 Ctrl、Shift 或 Alt 组合键时，可添加[粘滞修饰键](../features/keys/sticky-modifier-key.md)：先点击点亮一个或多个修饰键，再输入下一次符合条件的单键；再次点击同一修饰键可取消。仅启用 Shift 并输入字母时仍可参与 Rime 组合；其他快捷键的效果取决于方案与目标应用。具体消费规则见功能页。

空格键还能在编辑器里填「空格键标签」：留空时显示方案名与中英状态，填了就固定显示该文字，不影响输入与手势。
空白占位键用于排版，不接收输入；分体布局可单独配置断点和两侧排列。
二维码分享用于单份布局，不等同于完整应用备份。

方案已有以 ID 保存的子布局时，只列实际的 ID 条目，不再额外列同一方案的显示名称；仅用名称保存的旧布局仍保留原键，不会自动重命名。

子布局下方同一行的“合成中”在左、“分体键盘布局”在右。勾选“合成中”可查看已配置的合成态按键覆盖，不会写入布局或改变实际输入状态；文本编辑面板不显示此选项。

编辑分体排列时，在“键盘结构”的行设置中勾选“本行保持连在一起”，该行按整行显示，其余行继续分体。它也会关闭该行的自动中间键复制。操作与 JSON 字段见[分体键盘](../features/keyboard/split-keyboard.md)。

行标题栏提供新增、上移、下移等操作，首末行只显示有效方向；拖动结束后恢复卡片底色。
布局、宏、弹出和字体编辑器保留主体草稿及比较基准，页面重建后可恢复已确认内容。
后台草稿尚未准备好时仍保留同步保存兜底；这不等同于保证任意时点强杀都能保存所有未确认的选择框内容。

宏可组合文本、按键、光标移动、切层和设置入口。应用动作还可直接打开输入统计、JS 插件设置、自定义更新、数据与备份和键盘布局管理，或执行语音输入、AI 助手、分体键盘开关、日夜主题切换与随机主题，见[应用动作快捷入口](../features/editor/macrokey-editor.md#应用动作快捷入口)。修改后在实际输入框验证，
尤其检查 Shift、长按重复与跨层返回。旧布局保存的全局设置/引擎列表快捷方式会转到中州韵引擎设置。
编辑点击、长按或划动的宏动作时，对话框叠加在当前页面；确认后返回原表单，最终仍需保存布局。
动作选择“输入文本”后，点击输入框可调用系统输入法并组合输入、退格；从其他动作切换过来或新增步骤也可正常编辑。工具栏自定义按钮的宏编辑使用相同表单。

## 设置搜索与按键反馈

### 输入统计与键盘测试

默认分支已集成以下功能，需使用包含输入统计更新的构建。“输入统计与字词云”位于“设置 → 便捷功能”列表最下方，按方案及日、周、月、年或全部日期展示计数、速度、长度分布、词云和按键热力。统计和字词频次默认均关闭，词云需单独确认开启。计数与速度突出数值，单位和标签分开排布；词云按频次调整字号，以主色系渐变呈现并加粗高频前六项；热力图完整显示格式化后的百分比，非零且不足 0.1% 时显示为 `<0.1%`。输入趋势保留所选范围的完整总量，本年按月、所有日期按年汇总。

热力图缩小键间距，并固定键面文字大小，不随应用或系统字体设置放大，尽量直接展示完整键位。能够完整展示时不显示滑动提示；仅在窄屏或自定义键位确实放不下时，显示“左右滑动查看完整键位”并允许横向滚动。其他页面文字和按键频次条形图仍跟随正常字体设置。

只计原应用接受的整条纯汉字 Rime 提交，混合中英、数字或标点整条不计；键数和真实软键热力分别记录。密码、PIN、隐私输入、首次解锁前及输入法内部编辑不采集。数据保存在本机私有 `noBackup` 目录，**不包含在整包备份内**，请使用统计页的专用 JSON 备份。

速度分段看每次操作后是否仍有未完成编码；首键开始组词或顶功上屏后继续下一编码时，段内停顿会保留。隐藏键盘及结束、切换编辑器会结束当前速度段。

“清除所选范围”保留累计生涯字数，“清除最高速度”保留普通计数，“清除全部数据”则删除所有统计、生涯记录、本机导入前备份及其临时文件和统计分享缓存，并关闭采集。分享通过系统界面由用户决定发送；关闭、清除或恢复后，旧数据快照的分享会取消。完整口径、容量与操作见[输入统计](/features/input-statistics)。

普通设置页工具栏的“键盘测试”可切换文本、数字、密码和 PIN，通常为四列等宽标签，超大字号或宽度不足时改为等宽两行两列。PIN 使用真正的数字密码输入类型；涉及密码类型的切换、关闭面板或离开页面都会清空相应内容，不恢复测试草稿。普通文本仍遵循方案的正常学习及统计设置，在统计开启时可能计入数据；密码与 PIN 始终排除。

### 搜索与反馈选项

设置首页搜索支持中文名、英文别名和拼音；多个关键词需共同匹配，点结果会进入目标页并定位设置。先按要做的事搜索，例如“布局”“语音”“符号”“备份”。

首页“按需进入”末尾是“关于”，其中可打开用户手册、常见问题和版本更新；“开发者”位于“高级”页。当前首页已取消右上角三点菜单。

“键盘 → 按键反馈”可设置声音、振动等反馈。自定义音效支持 WAV、MP3、OGG、M4A、FLAC；文件不可用时回退系统音效。按键字体与候选字体分别在字体设定中管理。

空格滑动移动光标由“划动空格键以移动光标”开关控制；开始拖动后取消待触发的长按，慢速小幅拖动也可移动一格，光标步长可调至 16 dp。关闭光标开关后才使用布局里的自定义空格划动动作。
空格长按可选择切换方案、方案选单、语音或重复空格等行为；它与语言键短按切中英文是不同操作。

## 主题、字体与候选

外观页可切换和编辑主题、图标主题与字体：

- **主题**：“主题库”选用主题，“键盘样式”中的参数对所有键盘主题生效；随机主题可重新生成，并复制为自定义主题继续修改。内置「水彩」「普蓝」两套成套主题可一并换上配套布局、图标主题与按键副字体，也可只应用配色。副标签位置、未保存草稿与卡片操作见[主题编辑器](../features/theme/theme-editor.md)。
- **图标主题**：覆盖按键、工具栏、状态区标题栏、符号面板、剪贴板与文本编辑栏的按钮，主题未提供的槽位回退到内置图标，见[图标主题](../features/theme/icon-themes.md)。
- **字体**：按键、候选、注释和预编辑字体可以分别设置，见[字体集编辑器](../features/editor/fontset-editor.md)。
- **候选**：候选栏可调整字号、间距、注释、序号和外观；浮动候选窗口另有入口，位置可选四个角或“跟随光标”。万象拼音方案加载 `super_sequence` 时，菜单提供置顶、前移、后移和重置排序，排序结果由方案保存。实际加载并校验为 librime-evo 时，符合 editor 条件的方案按显式绑定独立提供前移、后移或「重置手动排序」；存在有效 `auto_delete` 绑定时，以「重置自动调频」替代既有「忘记此词」，按方案按键处理，否则仍保留名为「忘记此词」的既有候选删除入口，不重复显示二者。「重置手动排序」可单独显示且保留自动学习，EVO 不提供置顶；完整条件、动作语义与验证范围见[EVO 手动排序](../features/candidate-window.md#evo-手动排序)。其他候选设置见[候选窗增强](../features/candidate-window.md)。
- **设置界面外观**：“外观 → 设置界面外观”选择设置页的明暗模式、Monet、手动配色与纯黑背景，修改即时生效；预测性返回默认关闭。桌面主题图标与 Debug 图标见[设置界面外观](../features/theme/settings-appearance.md#应用图标与桌面主题图标)。

候选注释的内容由 Rime 方案控制；应用字体、颜色与间距只影响显示方式。
遇到中文缺字，先检查方案字集，再检查字体是否包含对应字符。

## 剪贴板、语音与文本编辑

便捷功能页提供剪贴板、符号和文本编辑；语音设置位于“输入与候选 → 语音输入”。
剪贴板同步和语音提供方有各自的配置、连接与权限要求，使用时查看相应页面。
这些是 Android 侧功能，不是需要另行启用的 Fcitx 原生引擎插件。

- **剪贴板**：键盘剪贴板页的搜索按钮在键盘上方打开浮动面板，按当前分组实时筛选，点击文本结果会粘贴到原应用；条目编辑同样在键盘上方的浮动面板中进行。见[剪贴板同步](../features/clipboard-sync.md#应用内剪贴板)。
- **JS 语音插件**：在“JS 插件设置”导入 `.js` 即可增加语音引擎，插件运行在输入法内置的 QuickJS 中；内置通义千问、豆包与腾讯云识别三个插件，密钥由宿主加密保存；通义千问与豆包还可把最终识别结果交给内置哔哩哔哩翻译翻成目标语言。使用前填写参数并批准插件的网络主机；工具栏语音键短按识别、长按切换首选引擎，密码框不显示语音按钮。换设备或卸载重装后，插件密钥需要重填。见 [JS 插件安装与使用](../features/voice-input-js.md)，接口参考有[中文译文](../features/voice-input-js-reference-zh-CN.md)和[英文原文](../features/voice-input-js-en.md)；外部语音应用见[外部语音输入](../features/voice-input.md)。
- **AI 文本助手**：在 Kawaii Bar 或状态区添加“AI 助手”，从“设置 → 便捷功能 → JS 插件设置”配置服务；输入问题后点击“发送 AI”，阅读回复后再点“确认上屏”。见 [AI 文本助手](../features/ai-assistant.md)。
- **JS 工具与翻译**：工具栏可从“JS 工具”模板添加直达 App；内置有道翻译与哔哩哔哩翻译，点击翻译后才联网，确认后才上屏。插件源码的导出、导入替换与恢复内置也在插件设置中。见 [JS 插件安装与使用](../features/voice-input-js.md#js-工具与内置翻译)。
- **符号面板**：“便捷功能 → 表情和符号”可选左侧分组栏或 Gboard 式底部栏，见[符号面板](../features/symbol-panel.md)。
- **文本编辑**：工具栏光标按钮打开编辑面板；在“便捷功能 → 文本编辑”选择默认或 Foxy 滑动风格。默认风格可自动识别或指定当前布局文件中的编辑布局，也可固定使用内置面板；设置页可直接编辑当前常规布局。Foxy 始终使用独立的 `text_editor` 底栏。水彩、普蓝配套的常规编辑键盘支持跨行方向键、长按重复与锁定选择，见[文本编辑](../features/text-editor.md)。

密码框默认不进入 Rime，键盘直接向输入框发送按键，并使用独立的布局回退与工具栏策略。需要在密码框里使用当前方案时，在「中州韵引擎 → 中州韵引擎设置」打开“允许在密码框中使用输入法”（默认关闭）；开启后密码框与普通输入框一样使用候选和中英文切换，但用户词学习、输入统计与语音输入仍然关闭。密码框不显示语音按钮。

重启后首次解锁前，文字密码可使用之前自动同步的当前自定义布局快照；没有可用快照、密码布局无效或只有空白占位键时回退到内置 26 键，数字密码使用数字盘。按键直接输入，不要求已导入中文方案。快照只同步当前布局；字体、图标和日常中文方案仍在首次解锁后的进程重启中恢复，锁屏模式不会覆盖正常设置。相关故障见[首次解锁前启动](../troubleshooting/oem-startup.md#重启后首次解锁前无法输入)。
不同应用对光标、组合文本、编辑动作的支持可能不同，异常时记录具体应用和操作步骤。

## 备份、迁移与升级

在应用内点击下载更新时，会先校验已有安装包并复用匹配文件；确认属于本应用、且已经安装的旧包在下一次下载前清理。文件按实际 URI 识别，重名附加序号不会单独决定是否可以安装，安装取消或失败不能成为删除依据。

本版恢复默认分支的包名 `org.fcitx.fcitx5.android.fx.rime`。
它可在签名相同、版本允许时覆盖原包名的旧 Fcitx 版，不能再与该版并排安装；安装前先备份。
旧直连测试包 `io.github.sandyyur.rime.direct` 与本版是两个独立应用，私有数据和应用外部文件目录不会自动迁移。
请先在测试包导出完整备份，再安装本版并恢复，检查方案、用户词库、布局与主题后再卸载测试包。
使用外部数据目录的，先强行停止旧包及其他共用者，再让新包访问独立工作目录；不要同时运行并共用用户库。

在“数据与备份”中导出完整用户数据，默认使用有密码保护的 `.fcbak`，也可明确选择兼容旧版的明文 ZIP。
页面顶部保留本次准备、保存与结果提示；失败后可再次打开错误详情。
密码没有复杂度要求，但不能为空；应用不保存密码，也无法找回。将文件保存到应用目录以外。
需要换包名、换签名或回退版本时，先备份并确认文件可以读取。
卸载会清除应用私有数据；同签名覆盖升级通常保留数据。

从旧 Fcitx 版迁移，优先在旧应用导出数据，再在中州鹅导入；
若完整备份格式不受支持，可先迁移 Rime 用户文件和单独导出的布局/主题。
不要把旧版其他引擎的词典或配置当作本版功能。

恢复完整备份前先备份当前状态。涉及外部目录时核对目标路径和最终替换范围；
恢复操作会替换目标内容。不要将公共存储根目录或包含其他用途文件的父目录作为恢复目标。

关于页的源码链接固定到正式 APK 的构建提交；用户手册与维护手册指向 `docs` 分支持续更新的文档，旧版操作需结合对应日期记录阅读。
“版本与更新”或“当前版本”可打开应用内更新器，检查 GitHub Releases、选择下载镜像并下载安装包；
关于页也会在检测到更新时提示新版本。更新器列出 Release 的全部安装包，请选文件名中 ABI 与设备一致的那一个（见[安装与升级](/guide/installation#下载主应用)）。联网失败仍显示当前版本，不影响其他设置。
导入、导出等耗时操作使用随设置主题配色的 Material 3 进度对话框；系统关闭动画时显示“请稍候”。
更新器的 hosts／镜像页面、日志与崩溃日志、方案导入、图片裁剪及剪贴板编辑也使用同一设置配色。
剪贴板编辑保持浮动窗口，布局文件选择保持透明背景上的选择弹窗。
安装与升级以成功 CI 或 Release 的实际源码、包名和签名为准；历史阶段报告不能代替当前安装包来源。
万象输入统计读取的发行代号现在为“中州鹅”，发行版本与 APK 的实际版本号一致；这不更改万象方案名。

## 隐私与数据

Rime 方案计算和用户词典在本机运行。剪贴板同步、网络语音提供方、下载或打开在线页面等
功能可能联网，取决于对应功能及提供方。请按实际需要配置。
完整备份可能包含用户词库、剪贴板历史、目录路径和同步设置。默认 `.fcbak` 使用密码加密，兼容 ZIP 不加密。
系统自动备份仅包含部分设置界面外观，完整迁移请使用手动备份；步骤与恢复中断处理见[备份与恢复](../features/backup-restore.md)。
反馈问题时先检查日志、截图和导出文件中是否包含个人输入内容。

## 保存日志与卡顿反馈

以下日志查看与历史保留说明对应 [PR #55 的日志系统改进](https://github.com/SandyYuR/fcitx5-android/pull/55)。PR 尚未合入时，旧安装包的界面与保留能力可能不同。

实时日志页顶栏提供搜索、过滤、刷新、清空和导出。搜索框按需展开，关闭搜索会恢复当前过滤范围的日志；过滤菜单可选择日志级别或 Rime 引擎日志。
日志区使用紧凑列表，按级别着色，并保留时间、进程、线程、来源和正文的完整日志前缀。点击条目可展开长内容。日志页不再显示键盘测试入口。

打开页面时，应用读取保留的应用日志，并与当前 logcat 快照合并，随后接收实时新日志。通过 `Logx` 输出的应用日志会同时写入私有文件；文件按日期、大小与时区变化轮转，采用单文件约 10 MB、总计约 30 MB、最近三天的清理策略。历史不会因离开日志页而立即消失，但仍会受保留策略及写入成功与否影响。原生引擎、Android 系统及其他仅写入 logcat 的记录仍受系统环形缓冲限制。

刷新会重新加载历史并接上实时日志。清空会删除应用日志文件、保留的崩溃报告及当前 logcat 内容；完成前禁止再次清空、刷新或导出。清空期间旋转页面会继续等待本次删除，已清空的崩溃堆栈也不会因页面或进程恢复而再次显示。

点击导出后可选择保存文件或分享。保存文件时，应用先冻结当前筛选结果、准备完整文件，再弹出系统保存位置选择器。
保存完成前不重复触发；取消选择后可重新保存。选择位置期间新增的日志不会改变已经冻结的这份文件。
只在文件写入并关闭成功后提示完成；保存失败会记录异常，并尽力清理新建的不完整目标。
保存和分享都包含设备与筛选信息，并附加仍在保留期内的崩溃报告；选择普通日志过滤条件不会移除该报告。崩溃报告最多保留一天，清空日志会一并删除它。应用日志与崩溃报告位于私有 no-backup 存储，不作为普通系统备份或完整用户数据备份的一部分。

反馈输入卡顿时，区分“刚唤起或切回输入框”“键盘已打开后的连续打字”“首次点选”“选词后立即发送”，记录具体步骤，
以及文字最终出现、迟到还是一直没有出现。`REQUEST_ACCEPTED` 只表示提交请求被接受，
不能单独证明文字已经显示或发送。分享前检查日志中的个人内容。

日志若以 `Persisted app crash` 开头，该段是此前保存的崩溃；请核对其中的时间和 `Crash build`，与后面的本次运行日志分开判断。

Rime 引擎默认仅输出 ERROR／FATAL；应用自身日志不受“Rime 引擎日志”开关控制。需要排查词典编译、部署或插件加载时，可在“设置 → 高级 → 开发者”打开该开关，让原生引擎把 INFO／WARNING 也写进实时日志。该开关在引擎初始化时读取，打开或关闭后都要重启应用才生效。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 没有键盘 | 检查系统是否已启用并选中中州鹅 |
| 有键盘但打不出中文 | 检查是否导入方案、当前目录与 `schema_list`，然后部署 |
| 以前学过的词、新学词都不出现 | 检查是否与其他输入法共用工作目录；强行停止其他使用者并重启中州鹅，随后分开工作目录 |
| 万象部署失败 | 核对 base 方案完整依赖、Lua、词典与模型，读取部署错误 |
| 部署日志仍报 failure，但能输入 | EVO 引擎在 `build/default.yaml`、方案列表、当前方案编译文件和主词典表／棱镜都存在时允许降级启动；仍需实际输入，见[部分部署失败时的降级](#部分部署失败时的降级) |
| 修改开关或 YAML 没生效 | 确认当前目录和实际方案，必要时重新部署 |
| Shift 不切换中英文 | 核对方案的 `ascii_composer` 和语言键宏动作 |
| 注释和预期不一致 | 核对方案注释开关与过滤器；应用不会追加额外候选编码 |
| 无法覆盖安装 | 核对包名、签名和版本；换签名前先备份 |
| 只有很简单的测试界面 | 安装了诊断 APK，应改用 Releases 的 `zhongzhoue-*.apk` 或带 `frontend` 名称的主应用产物 |
| 页面仍出现旧设置入口 | 确认安装的是当前分支新包，旧布局快捷方式应自动转到中州韵引擎设置 |

反馈时提供 APK 文件名或源码提交、Android 版本、输入框所属应用、方案版本、复现步骤，
必要时附上脱敏后的配置和日志。[维护手册](../maintainer/DIRECT_RIME_MAINTAINER_GUIDE_zh-CN.md)
提供现行构建与验证方法；[2026-10-17 交付记录](../maintainer/history/DIRECT_RIME_SESSION_2026-10-17.md)只保留当时的包与验证结果。
