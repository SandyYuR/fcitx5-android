默认分支固定产品与 PR #35 的职责拆分固定产品，均完成相同的候选点击和 Backend 工作负载。此前职责拆分记录中的功能测试及行数变化继续保持原范围，不自动继承为性能结论。

## 夹具与计时方法

复用既有 [Actions 43018095886](https://github.com/SandyYuR/fcitx5-android/actions/runs/43018095886) 的固定夹具 artifact `13853652309`，没有重新使用会移动的 LTS 下载地址。

原夹具清单中的历史产品字段保留当时记录；本次 APK 来源以本页及新的产品清单为准。

| 内容 | SHA-256 |
| --- | --- |
| 夹具 ZIP | `333e0a0c8c9beb8a942bd56d3f9c55f1c9123836635a4663744e23f21228404f` |
| 万象 v18.1.10 base | `ddebf0372a2a3d9d8f7a5017704b2afd7397a961c32be490a91e49ec3ee90999` |
| LTS 模型 | `769854c83f6c914a05a1e1abb67c31c00f1ae622a41878e05957bcdee3dbda9a` |

两台独立 Ubuntu 22.04 Actions VM，各使用 API 35 `google_apis/x86_64`、Swiftshader 模拟器。每台执行三个 ABBA 块，反序 VM 将每块顺序反转；每版每台六个 UI 测量进程及六个 Backend 测量进程。UI 与 Backend 分别启动 instrumentation，后者在再次停止并清空测试应用后执行，二者分别统计。部署、进程启动、视图查找和夹具准备在计时外。

首次点选也在部署完成、键盘可见及方案纠正之后计时。Backend 区间在夹具准备和预热之后开始；这些测量没有覆盖引擎激活、绑定准备、维护恢复或整体启动耗时，不能据此代表所有已拆职责的性能。

- 真实候选点击：每个 UI 进程输入 `ni`，点选“你”六轮。候选与 `n` 的计时起点均为 ACTION_UP 已派发到 IME Window 的时刻，InputConnection 终点为编辑器 `commitText` 的入口；注入等待及按住时间另存，不包含在这些区间中。首次一轮与后五轮分别统计；后五轮先求每个进程的中位数，再作跨进程比较。IME 与独立编辑器统一使用 `SystemClock.elapsedRealtimeNanos()`，保存原始纳秒与准确提交内容。
- Backend replay：每个 Backend 进程先预热 20 个词，再测量 100 个词。记录 `sendKey` 完成时间的 p50／p95／p99、进程 ART 分配、事件和提交序列。下表为每个进程相应分位数的中位数，不是所有按键混合后的分位数。

候选测量保留逐轮原始纳秒，可以重新计算各计时区间。现有 Backend 工作负载保存每个进程输出的分位数及同份 logcat JSON；本次核对这些原始输出，并重新计算跨进程及配对块统计。它没有保存逐键 duration，无法独立重算单个进程的原始按键分位数。

每版实际完成 12 次首次点选、60 次稳态点选（来自 12 个 UI 进程），以及 1200 个 Backend 测量词（来自另 12 个 Backend 进程）。每个 Backend 测量进程均为 100 个词、784 次按键操作，两版全部提交序列一致。24 组 UI 样本均通过六次准确提交、模型映射及逐轮时钟因果核验；合计 144 次候选选择和 2400 个 Backend 测量词。

### ART 分配与事件计数

下表 ART 数值是每个运行环境六个 Backend 进程、各自 100 词总分配量的中位数。每个进程的分配量来自测量前后计数差，包含进程内后台任务：

| 指标 | 正序默认 | 正序拆分 | 正序差值 | 反序默认 | 反序拆分 | 反序差值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 分配对象数 | 49,938.5 | 53,988.5 | +4,050（+8.11%） | 49,881 | 53,992 | +4,111（+8.24%） |
| 分配字节数 | 3,375,104 | 3,358,720 | −16,384 | 3,342,336 | 3,325,952 | −16,384 |

12 个默认版进程的对象数范围为 49,794～49,964，12 个拆分版进程为 53,894～54,107，两个范围分离。六个配对块的对象数差分别为正序 +4,111.5／+4,025／+4,131.5、反序 +4,175／+4,050／+4,095，方向全部一致。这是尚未定位的对象分配增加信号，不能仅因部分延迟波动而忽略，也不足以单独确定具体职责类或 GC 影响。源码及已构建 DEX 的只读排查尚未找到可安全归因、修正的点，不将这项进程总计数直接指向某个 helper。

本组分配字节观测值以 32,768 字节步进变化，组中位数减少 16,384 字节不能解读为节省内存。对象数、分配字节、峰值／常驻内存和可感知延迟不是同一指标。

默认版每个 Backend 样本收到 784 个 `InputPanelEvent`／`PagedCandidateEvent` 展示事件；拆分版正、反序各一个样本为 783，其余为 784。这类计数允许相邻纯展示事件合并，不能据少一个展示事件推断丢键；两版全部 784 次操作与 100 次准确提交仍一致。各进程的原事件计数保存在附件。

Debug 构建及共享宿主上的虚拟设备会受调度、JIT 和运行环境影响。本次不依据这些信号直接修改生产代码或宣称 Release／真实手机性能变化；后续如定位对象分配或首次输入成本，须保持产品、夹具和计时口径，再对症复测。
