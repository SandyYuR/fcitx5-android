# DirectRimeBackend 审查核对与调整建议（2026-11-12）

用户提供的审查基于浅克隆的 `2e48466`。本次对照当前默认分支冻结源码 `0380d70f`，结合已完成的[输入延迟调查](../perf/wanxiang-2026-11-08/supplement-2026-11-11/investigation-2026-11-11/index.md)，核对哪些建议仍适用。**职责集中确实存在，但大规模拆类不是已证实的首键卡顿修复。** 当前 `DirectRimeBackend.kt` 为 955 行，适合逐步整理。

这份核对不复核其余六个项目的实现，也不把文件数、断言数或给出的等级当作当前覆盖率。当前事实和后续建议如下。

## 需要校正的描述

| 审查描述 | 当前代码与证据 | 对优化的影响 |

JNI 异常、资源清理、owner、门控、维护恢复、保存开关与提交顺序仍是要保持的约束。审查里提到的可靠性方向成立，具体实现继续以固定源码与实际测试为准。

## 先抽哪些职责

| 顺序 | 建议范围 | 设计边界 | 验证重点 |
| --- | --- | --- | --- |
| 1 | 状态区与菜单的纯组装：`buildActions`、动作格式 | 接收方案、开关行、状态与当前语言文案，返回不可变展示；不调用 Native、不启动协程 | 互斥组、ASCII 目标文案、方案勾选、ID 与选中行为；语言变化不能命中旧资源缓存 |
| 2 | Snapshot 到 client/preedit/panel 的转换，以及音节动作组装 | 接收只读快照与显示选项；`candidateVersion`、提交产生时间、原子发布与事件 offer 仍在协调入口 | UTF-16 光标、预编辑模式、提示寿命、音节跨度、空状态及过期代次 |
| 3 | 方案、目录、导入和资源更新命令 | 以少量显式回调使用现有维护入口；保留停止、安装、回滚、重启的事务边界 | 取消、失败恢复、维护期间绑定变化、无变更更新、不复活旧 session |
| 后续 | 维护协调、绑定与事件排空的组织 | 先明确谁拥有状态；不搬进共享可变状态袋，也不为每个组件新建 scope/dispatcher | start/stop 竞态、ticket、背压、旧编辑器写入拒绝和提交无丢失 |

`DirectRimeBackend` 继续作为前端协议与单 owner 的协调入口。提取纯转换函数可以改善测试和阅读，而不增加调度；异步的准入与事务分散则会增加需要证明的顺序关系。优先提取较冷的维护命令也能显著减少类体积，不必为了行数改写输入热点。

维护命令的内部接口应接收“已经在 owner 上执行”的同步 Native 回调，不能在 owner 内再次调用会 `runBlocking` 等待停止的公开 `stop()`。事件队列的容量等待也继续位于进入 owner 之前。抽取文件时保留这两点，避免把原本正确的线程边界改成互等。

本次没有执行上述 Backend 拆分。候选栏性能修复在独立代码分支验证，先保留状态所有权，以便判断性能变化的来源。

本轮在后端落地的范围较小：`act()` 原本已将 Native 动作和结果发布放在同一交互优先级作用域，`sendKey()` 则在发布前恢复优先级。修复版统一覆盖按键的同步发布与转发入队，保持原优先级数值、异常恢复和队列边界，并增加发布分段 trace。此项不是拆类，也不能减少 `RimeProcessKey` 内部首次计算；[三轮验证](../perf/candidate-latency-fix-2026-11-12/index.md)仍保留较慢的首键和分发样本。

## 性能上的具体检查点

`publish` 仍会组装 `FormattedText`、tabs、候选与目标。这些是可进一步分析的分配位置，但不能直接把它们解释为本次 53–59ms 的 Rime 调用：三次首键 snapshot 只有 0.624–0.801ms，native 线程在 `process_key` 中有约 18–20ms CPU 和显著等待；另外首次候选布局有约 11.94ms 主线程 CPU。

因此当前优先缩减候选布局、文本与视图构造的重复工作，再用相同配置对照。首次 native 计算需要继续分段，不通过关闭上下文调频、用户学习、音节选择或减少候选功能来制造收益。

展示优化必须遵守以下限制：

- 不能复用带旧 commit 的快照，不能跳过接受的副作用事件。
- `CandidateWord` 的显示相等不包含选择目标，不能修改已发布对象的 target 来假装新代次；否则旧 holder 或分页会被重新授权。
- tabs 的缓存键至少要覆盖 generation、tabsRevision 及对应文字/跨度，必须有界并按维护与会话规则失效；仅比较可见文字不足以证明安全。
- 能跳过重复布局和纯文字 span 分配，不代表可以跳过真实字体、注释字号、高亮前景或触摸目标更新。

## 可观测性与测试补强

现有自动构建和正确性回归继续保留。共享 Actions VM 上的调度和软件图形噪声很大，性能可定期保存固定配置趋势，不宜立即把一个单次 wall time 阈值设成 PR 成败条件。先完善同机对照、顺序轮换、原始时间和异常保留，再形成持续基线。

JNI 覆盖可先增加真实设备上的异常、编码及资源边界测试，并评估 CheckJNI / 可用 ABI 的 sanitizer；故障注入要确认最终 Java 异常和引用清理，而不只验证主机 fake API。此项属于后续可靠性改进，本轮未修改 JNI 或引擎 SDK，也未宣称已补齐覆盖。

架构页、现行契约和日期实测各有用途：架构页帮助新人建立整体理解，契约定位不能破坏的行为，实测报告记录特定版本与环境的结果。源码调整时同步前两者，旧实测证据保留原字节。
