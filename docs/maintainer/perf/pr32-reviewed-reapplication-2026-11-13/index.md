# PR #32 旧优化审阅、改写与重新对照（2026-11-13）

**组合版仍有偏慢信号；仅 UI 版的独立复核未证明稳定收益，本轮不恢复这些性能改动到 PR #32。** 修正版完成 80 个新进程、480 次正确选词。组合版首次完整 i 两台 VM 的配对区组差中位数为 +4.363ms／+11.568ms，均为三慢一快，触发筛查排除。仅 UI 版复核的首次完整 i 为 +4.803ms／−2.756ms，两台均三慢三快；首次点选为 +0.217ms／−0.898ms。没有跨 VM 一致的复核退化证据，也没有达到事前稳定收益门槛。

本次针对用户要求重新研究原先撤下的改动，先修改实现，再进行隔离对照。基线是 PR #32 已收窄的字体正确性与采样修复版，并非无字体修复的旧默认版。本轮没有重新测试 Fcitx 版，也没有将上次试验的数字当作本轮样本。代码 PR [#32](https://github.com/SandyYuR/fcitx5-android/pull/32) 保持草稿；默认代码与文档分支均未推送或合并。

## 先行发现与修正

[第一版完整筛查及启动失败记录](./initial-screen/index.md)保留 32 个新进程和 192 次正确选词。第一版 UI 的首次完整 i 两台 VM 均为三慢一快，差中位数 +26.185ms／+3.683ms，按预登记排除；组合版尚未触发筛查排除，但手工检查又发现 `TextPaint(Paint)` 与 `set(TextPaint)` 的七个附加字段语义不同。它们不再具备采用条件，不论计时是否好看。首轮复核在启动模拟器前因内嵌 Python 换行错误退出，实际复核进程为零，原始启动附件保留。

本报告对应第二版准确源码：使用未修改的构造等价模板重置，多段最多两份 Paint，单段保持一份；加强样式断言覆盖全部七个字段，同时修正发键前的脚本并验证六种顺序绑定。重新登记源码和随机种子，其他采样规则及采用门槛不变。没有重跑同一有效版本以替换不利数据，也不将第一版样本加入第二版分布。此正确性发现不是上次性能倒退根因的证明。

## 代码审阅与取舍

| 原先涉及的改动 | 本次处理 | 理由与边界 |
| --- | --- | --- |
| 每个 span 段创建 TextPaint | 单段仍只创建一份 Paint；多段最多两份，以未修改模板重置后应用样式 | 保留逐段新建 Paint 时的七个附加字段默认值及所有 CharacterStyle 类型与逐段样式调用；不跨遍历共享可变 Paint |
| 角标关闭时仍创建 TextView | 按首次显示需求创建，隐藏后保留 | 保留默认样式、父容器 LayoutParams、四角定位、颜色与无障碍属性 |
| 每次绑定都写 Flexbox 参数 | 仅在实际 minWidth 或 flexGrow 不同才更新 | 第二次布局仍可改变参数，不以“曾绑定”缓存代替真实状态 |
| 每个按键仅 Native.key 在显示优先级内 | 将 Native.key、统计结果组装、publish 放在同一次优先级范围 | 与已有候选动作一致；日志和转发记账在外，未增加每键优先级切换次数 |
| 移除 TextView 默认样式 | 不恢复 | 构造样式会影响兼容行为，不能凭行数推断性能收益 |
| 只按 MetricAffectingSpan 测量 | 不恢复 | 普通 CharacterStyle 也能改变字体、字号或比例；不缩窄现有契约 |
| 无注释候选／高亮快路径 | 不恢复 | 保留原正文和注释 span 结构，避免把先前的语义改动与本次分配改动混测 |
| 缓存 String 代替每次读取 CharSequence | 不恢复 | 任意可变 CharSequence 的可见内容可能变化，维持原观察行为 |

Paint 分配数从每段一份改为单段一份、多段最多两份；因此一段或两段文字本身不减少 Paint 分配，可能的收益只来自更多段及其他 UI 改动，不能凭代码变化推断提速。

字体失效修复保持不变。引擎、SDK、方案、模型、Lua、用户词库语义、owner／事件队列与候选代次门控均未更改。优先级改动只覆盖既有单 owner 内的结果发布，没有把整个 sendKey 或转发链路提升优先级。诊断构建才分配时间戳载体，普通构建无此数组分配。

## 预登记与方法

[计划](./reapply-plan.json)在 dispatch 前提交。SDK android-sdk-20261110-1／librime b5561910，锁摘要 6500f364…；万象 v18.1.10 base＋2026-11-07 LTS，沿用全拼、上下文调频、简码、小字集 YAML，fixture 43018095886／13853652309。API 35 AOSP ATD x86_64、KVM、软件图形；100ms 计划 n/i 间隔，显示原配置注释，不采 trace，不注入暖机文字。沿用独立进程 InputManager v3 发键器，全部触摸验证实际保持至少 20ms。

第一阶段是两台新 VM 的四版 Williams 方阵筛查：每台四个区组，每版每区组一次，32 个新进程、192 次正确选词。每版在四个位置各出现一次，12 种有向相邻组合各出现一次。配对单位为同区组的试验版减 baseline，分别报告两台 VM 的四个区组，不能把每次选词当作独立冷启动。

筛查排除规则：若任一冷态主指标在两台 VM 的配对中位数均为正，且每台至少 3/4 区组更慢，则排除该方案。其余按预定顺序 combined → ui → priority 选一个进入独立复核，**不按观察到的最快中位数挑版本**。所有方案被排除则结束，保留负向结论。

复核若执行，则另用两台新 VM、同一份 APK 字节。每台六个区组，恰好三 ABBA、三 BAAB，共 48 个新进程、288 次正确选词。每个区组取两次试验版均值减两次 baseline 均值。筛查和复核不混池，也不替换不利样本。ui 的三项修改作为一组处理，不能据组间数据断定其中某一项是偏慢的唯一原因。

采用门槛同样事前固定：正确性全过；复核至少一个冷态主指标在两台 VM 均为负中位数且至少 5/6 区组更快；两个冷态主指标均不得在两台 VM 同为正中位数；后五轮任一指标不得在两台 VM 同为正中位数且至少 4/6 区组更慢。这是保守工程门槛，不是正式统计非劣证明；未达标即不自动采用。

Actions 成功表示构建、正确性检查与采样链路完成；是否采用性能改动，由独立复算后的事前门槛判断。

## 解释与决定

**最终保持 PR #32 的 2e86e2ec 不变**：保留字体测量缓存正确性与采样可靠性修复。重新应用并改写过的 UI、优先级、组合版本均保存准确源码、补丁和实际测试数据，未自动采用。默认代码、docs 与用户另建的重构分支未由本次修改。

组合版首次完整 i 在两个 VM 的四个区组中各三慢一快，触发事前排除；这是需要保留的偏慢信号，样本仍不足以推出所有设备上的固定退化幅度。不能因后五轮点选某个中位数好看而忽略它。priority 版只有筛查，没有独立复核，不将其描述为已证实改善或已证实退化。

仅 UI 版独立复核的首次完整 i 两台均三慢三快，差范围为 −42.063～+24.527ms、−14.884～+19.980ms；首次点选分别四慢两快、三慢三快，差范围为 −2.799～+1.515ms、−6.618～+1.850ms。两个冷态主指标都没有同时达到两台 VM 至少五个区组更快，故未满足采用门槛。与此同时，冷态主指标没有两台同为正中位数，后五轮也没有触发跨 VM 一致偏慢规则，**不能把这个不确定结论写成“仅 UI 版已证实负优化”**。

后五轮完整 i 差为 −0.020ms／−0.0004ms，后五轮点选差为 −0.643ms／−0.043ms；后者在两台分别一慢五快、三慢三快，不能据此宣布普遍提速。首次 i 实际 UP → 窗口 UP 差为 −0.024ms／+6.562ms，反向四慢两快；首次实际保持差为 −9.454ms／−7.425ms。各阶段中位数不可相加，触摸调度差异也要求保留，不能只用反向完整 i 的负中位数宣布收益。

本轮确实修正了重新实现时的 Paint 字段语义边界，并补齐七字段断言，但这项正确性改写不等于性能改善，也不是对上次回退唯一根因的证明。少创建 Java 对象仍伴随 Paint 状态复制与调度成本；本次未采 trace，无法把某个区组差归结为某一行代码。

第一版另有 32 个新进程、192 次正确选词，复核启动失败前没有采到任何复核进程。与本轮只合计记录数量为 112 个新进程、672 次正确选词；不同源码、VM、阶段的时延分布始终分开。所有有效不利样本保留，没有为替换结果而重跑相同版本。

绝对中位数之差不等于配对区组差中位数，各阶段中位数也不能相加解释全链路。首次 i 指实际注入 DOWN → IME 窗口 UP，包含真实保持时间及主线程等待；候选窗口 UP → IC 指编辑器 InputConnection 入口，尚不是屏幕发光。触摸实际保持、注入迟到及计划／实际时间均另列原值。首次与后五轮进程内中位数分开，后五轮不是五个独立进程。

本轮只测 API 35 x86_64 Debug 模拟器，在卸载重装、恢复夹具且键盘与方案绑定就绪后发键。不能推断真机、ARM、Release、长时间个人词库、绑定未完成的首键、P95 或总体吞吐率。没有 trace，数字变化不能单独锁定引擎、调度或绘制根因。
