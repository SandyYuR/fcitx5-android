## 问题与修改

| 问题 | 原因与处理 |
| --- | --- |
| `.temp.userdb` 导致同步失败并崩溃 | librime 枚举把恢复流程的 `.temp` 临时库当成普通词典，读取失败后同步返回 false；状态区点击启动的协程没有接住异常。引擎通过 `ListUserDictNames` 跳过精确保留名称，保留目录内容；状态入口通过 `activateStatusAreaAction` 报告失败，备份侧仍接收真正失败 |
| 跟随键盘取色后 AI 控件无法创建 | 颜色资源包装 Context 缺失完整的控件主题。新包装显式应用 Settings 浅／深基础主题，再叠加键盘色板，覆盖输入框与 MaterialButton 的实际构造回归 |
| 剪贴板编辑导致键盘重复弹出 | 条目与工具栏长按入口改为 `ClipboardEditor`，复用 IME 附着面板与本地输入连接，不启动独立 Activity。旧 Activity 保留给历史外部调用；保存、复制和取消继续遵循原事务顺序 |
| 布局收起后高亮底边异常、默认全展开 | 收起时移除正文留白，由整张卡片绘制高亮；新页面默认只展开当前启用 profile，手动展开状态在本页与旋转时保留 |
| 随机按钮位置和卡片留白 | 骰子移到底部，与编辑同排。名称仍是一行，标准字号卡片 140 dp；图标视觉行 32 dp，通过父级扩展到 48 dp 触摸范围 |
| 更新包重名与清理 | 采用用户建议的下载前检查。私有下载记录保存实际 ID／URI、内容摘要和发行身份；旧版自有 DownloadManager 完成记录也可核对。只有与当前已安装 base APK 字节摘要一致的自有旧下载可删除，匹配本次发行的新包复用，其余保留。新下载使用唯一目标名，既有无空格／有空格的序号名均可校验 |

## 临时库来源与追加审阅

`UserDictManager::Restore` 用 `.temp` 接收待合并的用户词典快照，再合并进真正的目标库。同步目录中的 `*.userdb.txt`（包括本机先前生成的快照）、显式恢复以及旧词典格式升级都会进入这条路径。正常作用域退出会关闭并清理临时库；进程中断、打开失败（清理守卫尚未注册）或删除失败可能残留。用户提供的日志只说明残留被误枚举，不足以确定它最初出现的具体时刻。

2026-11-07 追加审阅保留精确过滤，不扩大为忽略全部点开头的词典；也不将底层同步失败改成成功。新增真实 LevelDB 回归已经验证普通词典备份、其他设备快照合并、坏库仍失败且正常库内容保留。状态菜单测试同时检查正常错误报告和协程取消传播；APK 的 `PluginSdkSmokeTest` 追加实际已学习词条在临时库残留下的同步检查。

Android 模拟器进一步复现 Lua 学习后的同步失败：日志显示仅同步一个真正的 `sdk_smoke` 词典，`.temp` 已正确排除，但该词典无法以备份方式重新打开。仅销毁会话不会立即回收 Lua `Memory` 持有的词库。应用 JNI 维护入口因此先释放引擎模块，再以非强制方式初始化和同步；复用进程级 setup，不改 SDK 资产、不删词库或 LOCK，也不把这一失败改为测试跳过。原始失败保留在 Direct Rime CI `42258895942` 与追加日志的 `42260254454`，后续回归必须使用相同的真实 Lua 学习测试。

已下载源码 `483ffbca5fdfa8a13698d28085e3154d48e435b3` 的 SDK 主机测试 XML，三个针对性回归均实际执行通过，摘要见[同步回归证据](../audit/device-fixes-20261107/sync-regression.json)。整个主机报告中 208 项执行，另有上游原有的 `DISABLED_CaseTranspose` 未启用；未启用项不计为通过。

## 下载清理边界

更新本体会停止旧进程，因此不依据安装 Activity 的返回事件删除文件。检查与清理仅在下一次用户点击下载时运行，并在 IO 线程完成。安装取消、尚未安装、文件内容被修改、来源不明、下载记录不可访问时保留文件。服务端不提供摘要时，不能因“同名同大小”复用另一发行的包。

新包安装仍使用实际 URI 和系统安装器。DownloadManager 持续验证按已记录 ID 查询，避免重新按文件名选到旧包；hosts 下载保留 WorkManager 的后台生命周期、校验与发布逻辑。
