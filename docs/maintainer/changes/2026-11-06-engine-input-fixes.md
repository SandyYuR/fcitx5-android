### 候选版本与序号

`CandidateSelectionTarget` 随候选生成，保存编辑器/候选版本、原始序号及当前页/全局含义。点击不再只把一个序号排到队列中，也不在执行时用新列表替换旧点击的身份。

展开列表在异步刷新时可以暂时保留旧页面，但该页面仍保留旧目标；不会因第一屏收到新事件而被标成新版本。adapter 与 holder 显示内容不一致时拒绝操作。相同文字只更新目标元信息，避免整行重新布局；候选生成器同时观察版本，以免漏刷内容变化的懒候选尾部。

### 展示与原始编码坐标

native action 13 读取当前输出，不调用 `set_caret_pos`，因此不再为一次展示刷新重新 Compose。待提交文字仍按新结果消费一次，不重播旧快照的 commit。同模式重新呈现不伪造候选版本变化。

真实光标请求先核对排队时的编辑器和预编辑文本，再通过 `Native.rawInput(generation, revision)` 读取原始编码/光标。该读取不消费提交、不推进 native revision，也不增加每键的数据打包。

坐标映射区分 Unicode 码点、Android UTF-16 和原始 UTF-8 字节，支持可确定的文字、显示分隔符及当前光标边界。任意转换文字不能一般性地逆推编码位置；无法确定时重新发布当前 client preedit，使编辑器恢复到引擎位置。“候选预览”不按预测词的位置编辑编码。

Android 回归使用加入显示空格的真实方案：`ni` 显示为 `n i`，在显示位置 2 移动后插入 `a`，应得到 `nai` 的“奶”，而非 `nia`。

### 同步与备份

`sync_user_data()` 的启动结果与后台完成结果分别处理。调用开始时重新登记本次状态，等待线程完成后才返回成功；任何失败在同次维护内保持有效，不能被后续成功通知覆盖。缺少终态、启动失败、异常和重试都有回归覆盖。

同步会清理原生 session。运行时 `save()` 进入相同维护门控，避免同步期间接受输入或复用失效句柄；未启动的引擎仍允许备份流程导出现有文件。真正复制备份仍使用原有停止写入协议。

### JNI 展示数据复用

每次 native 按键处理和提交读取继续执行。只有未处理、没有新 commit、同代次且全部展示值相同的结果才复用 Java 字符串和数组；`Snapshot.reusePresentation` 新建快照，更新 revision，清空旧 commit，旧快照保持不变。

缓存仅保留最近一份，文本预算为 64 KiB、四组数组字符串总数至多 1024；过大或不可用状态走完整打包，停止、部署和同步返回时清理。接收方按只读值使用数组。这个预算不等同于进程内存上限。

本轮减少的是 JNI 对象和字符串/数组的重复构造，没有省略 `process_key`、`get_commit` 或 `get_context`。Android 测试校验了数组引用复用、旧 revision 不变及 commit 不重复；没有据此宣称真机 P95 或耗电改善百分比。

### 方案菜单与密码模式

首轮完整前端设备验证发现，密码场景下的方案菜单把前端 `abc` 标记当成方案名，因此选中标记不正确；原设备测试也用该模式标记判断方案切换成功。

现改为从同一份方案动作列表读取勾选状态和动作 ID。设备测试分别检查实际方案、菜单勾选、密码直接输入、焦点、键盘可见性及编辑器文字，未通过改变密码行为来满足测试。

### UI 兼容性与翻译

常规 PR CI 随后检出近期 UI 改动遗留的 17 条 lint 错误：光标颜色接口的 Android API 29 要求、标题控件的 AppCompat 继承要求，以及 14 个文案键缺失翻译。现为光标配色添加版本判断，标题使用 `AppCompatTextView`，补齐德语、俄语、韩语、日语和西班牙语文案并校验两处格式占位符。项目继续支持原来的最低 Android 版本；lint 配置与 CI 检查保持有效。
