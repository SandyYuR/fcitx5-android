# 草稿保存一致性与后台 JSON 准备 · 2026-10-26

本轮继续修复 `perf/direct-rime-startup-20261024` 的草稿保存链路。[完整来源与验证边界](./provenance.json)。

## 保存一致性

- 用实际 JSON 内容去重，避免 `{"label":"Aa"}` 与 `{"label":"BB"}` 的相同 `String.hashCode()` 导致后一次编辑漏存；从文件读回的草稿同样按内容判断。
- 先写同目录唯一临时文件，再通过 rename 发布完整版本。写入或替换失败时，旧的完整快照保持可用；生命周期 Bundle 在大草稿保存失败后保留上一份成功快照的引用。不能据此保证失败前最新一次编辑已经落盘。
- 拒绝草稿文件软链接，包括指向同目录另一草稿的链接；过期临时文件只清理本存储器严格命名的文件。
- 发布前注入异常/替换失败测试验证旧文件不受损、临时文件清理与再次保存。该验证覆盖进程中断窗口的文件状态，不代表物理断电持久性或 fsync 保证。

第一批[完整构建与回归日志](./integrity-tests.txt)保留。

## 后台 JSON 准备

已完成的编辑操作复用撤销历史中的独立深拷贝，在 `Dispatchers.Default` 生成 JSON。ViewModel 保管缓存，不持有 Activity；只有一个编码任务，连续请求只保留最新待处理文档。页面所有者销毁会取消任务与完成句柄，旧版本不会发布到缓存。

`onSaveInstanceState` 读取缓存前逐段比较当前布局、嵌套宏、横竖屏高度、辅助栏配置与按键。内嵌表单的未完成编辑不会误用较早快照；缓存缺失、准备失败或内容不匹配时保留原同步导出兜底。序列化失败也尝试保留已有成功快照引用。

**D7 仍是部分修复**：上述兜底仍可能在 Main 序列化；生命周期草稿文件写入也仍在 Main。不能将后台准备等同于保存全过程已移出主线程。
